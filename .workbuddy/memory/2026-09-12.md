## Electron dev 启动环境排障结论（小白沙箱环境专用，用户本机无此问题）
- 根因一：WorkBuddy 沙箱 shell 继承了 `ELECTRON_RUN_AS_NODE=1`，electron.exe 会以纯 Node 模式跑 main.cjs，`require('electron')` 解析到 node_modules/electron/index.js 返回路径字符串 → `protocol`/`app` undefined。启动前必须 `unset ELECTRON_RUN_AS_NODE`。
- 根因二：沙箱拦截系统读取（如 `C:\Users\admin\.ssh`），Chromium GPU 子进程反复 exit_code=1 → FATAL "GPU process isn't usable. Goodbye."。需加 `--no-sandbox --disable-gpu --in-process-gpu` 启动参数。
- 可用启动方式（分两步，绕开 npm shim）：
  1. 后台起 Vite：`node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`
  2. `unset ELECTRON_RUN_AS_NODE && ELECTRON_RENDERER_URL=http://127.0.0.1:5173 ./node_modules/electron/dist/electron.exe . --no-sandbox --disable-gpu --in-process-gpu`
- 此前误判：曾以为是 `process.defaultApp` 废弃导致 remoteKnowledgeConfig 路径判定失效（Electron 41），实际上那次报错也是 ELECTRON_RUN_AS_NODE 环境下的副作用；对 remoteKnowledgeConfig.cjs 的 fs.existsSync 改动无害可保留。

技术设计 2/3 · 操作规则与异常处理

三类操作都只生成候选，不自动保存。应用候选时严格使用请求发起时记录的草稿快照与字符范围，防止 AI 结果写错位置。

无选区 · 光标定位

从光标处续写

结合本小节上下文继续写，不重写光标前后的原文。

各阶段成果均执行内部审核和用户确认。AI 候选插入到这里，不覆盖任何已有字符。后续工作按照验收意见持续优化。
输入章节标题、描述、当前草稿、光标前后文、用户补充要求，以及 Main 侧已有项目事实。
输出只返回要插入的新 Markdown 正文，不返回章节标题、代码围栏或原文复述。
应用在 selectionStart 处插入，并自动补齐必要的段落换行；光标移动到新增内容末尾。
存在选区 · 精确替换

改写选中内容

选区是唯一可替换范围，选区之外的正文不交给模型改动。

项目团队将定期沟通项目进展，及时处理出现的问题，确保实施工作有序推进。
输入选中文字、前后文、章节目标及用户指令；快捷要求包含更专业、扩写、缩写和增强可执行性。
输出结构化返回 replacementText；右侧抽屉展示修改前后对比。
应用仅替换 selectionStart 到 selectionEnd。若选区包含图片保护块，则拒绝执行并提示仅选择正文文字。
光标锚点 · 图片块插入

在当前位置插入图片

AI 生成、本地选择和剪贴板粘贴最终使用同一正文图片块。

项目实施分为六个阶段。项目实施阶段示意图各阶段设置明确的交付成果。
来源AI 图片：填写图片描述；本地图片：文件选择或拖入；剪贴板：在抽屉中按 Ctrl+V。
预览先展示图片、图片标题和图注；用户可重新生成、重新选择或放弃。
应用插入独立 Markdown 图片块，不替换文字。存在选区时默认插在选区末尾。
状态或异常界面与处理规则
当前处于预览模式“AI改写”不可用，并提示先切换到编辑；因为预览页面没有稳定的字符光标。
正文任务运行、暂停中沿用现有编辑锁定，AI改写、应用候选和章节保存全部禁用。
AI 请求期间草稿被修改允许用户继续阅读，但应用时比较 draft 快照；不一致则拒绝覆盖并提示重新生成。
连续点击或重复请求同一抽屉只允许一个运行请求；生成按钮进入加载态。新请求使用 requestId，迟到结果自动忽略。
模型调用失败保留用户指令、选区和上下文，错误显示在抽屉内，并提供“重试”；不改变草稿。
图片模型未配置或不可用只禁用“AI生成”，本地选择和粘贴仍可用，并给出可操作提示。
选区跨越图片块不把图片 Markdown 交给模型，提示“请选择纯正文内容”；图片块按原子内容保护。
用户应用后反悔应用成功 Toast 提供一次“撤销本次应用”；点击页面“取消”仍恢复进入编辑前的已保存正文。

图片资产规则

  • AI 图片和本地图片统一复制到当前项目的 technical-plan 图片目录，不写入 blob URL 或 file://。
  • 正文使用 yibiao-asset URL，现有 Markdown 预览和 Word 导出链路可直接读取。
  • 用户放弃尚未应用的候选时立即删除临时图片；启动时可清理长期未引用的候选文件。
  • 本地首版支持 PNG、JPG/JPEG 和 WebP；粘贴图片统一保存为 PNG。

独立的手工插图块

  • 不复用“全文自动配图”的 yibiao-illustration 标记，避免后续重新编排图片时误删用户手工插图。
  • 新增 yibiao-inline-image 标记，并在局部文本操作、查重替换和导出前处理中将其视为不可拆分块。

# 正文迁移恢复默认处理方式

用户要求删除不必要的批量直迁，并能够恢复之前确认的默认规则。

设计：用“恢复默认处理方式”替换“批量设为直接迁移”。默认方案沿用当前目录、确认差异和历史正文定位规则：地点/实施对象、工作量、工期进度命中的章节局部改写，其余可靠来源直接迁移，无来源待人工处理。清除人工策略及要求，保留所有正文；人工正文及其审核状态保留，自动生成正文标记待重新迁移。一致性检查和阶段确认失效。按钮显示简短用途说明，编辑草稿未保存时禁止重置。“执行待处理迁移”更名为“一键迁移待处理章节”，区分批量操作与“按此方式迁移本章”。

实施顺序：

- [x] 修改现有 Store 测试，覆盖重新计算默认、清除人工策略、保留正文、人工正文不重迁移、检查失效和持久化；先运行失败。
- [x] 替换 Store 批量直迁入口为重置默认，同步 IPC 注册、数据库通道、preload 和类型。
- [x] 替换页面按钮和提示，重置后同步当前下拉框，包括尚未应用的选择。
- [x] 更新浏览器回归，覆盖默认局改、人工选择恢复、无来源、草稿保护和阶段流程。
- [x] 运行定向测试、CJS 检查、native smoke、生产构建和浏览器回归。

验证结果：定向测试 38/38 通过，补充持久化重开断言后 Store 测试通过；四个变更 CJS 文件语法检查通过；`npm run smoke:electron-native`、`npm run build` 与完整浏览器回归均退出 0。构建只有既有 chunk 体积提示。浏览器回归的提示关闭逻辑改为每次重新定位第一条提示，避免列表重排漏关后遮挡操作按钮。

只修改上述范围，不处理已有 package-lock 冲突，不提交或发布。

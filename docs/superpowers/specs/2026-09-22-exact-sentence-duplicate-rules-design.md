# 两份标书完全一致句子规则设计

## 背景

“同源正文对比查重”当前会把段落中的短语、词语或被句内标点切出的片段识别为“完全一致句子”。这会让查重结果偏离人工理解：只有完整的一句话相同，才应该进入“完全一致句子”统计。

## 目标

- 以完整句子作为“完全一致”的唯一比对单位。
- 排除词语、短语、标题片段和短口号。
- 保留空格、换行、句末标点差异的归一化能力。
- 不改变“相似段落”的现有判断逻辑。
- 不修改数据表结构、IPC 协议或结果持久化格式。

## 判定规则

### 句子边界

- 中文句号、问号、感叹号，以及英文句号、问号、感叹号作为句末边界。
- 英文句号继续避开小数和常见缩写。
- 逗号、顿号、分号、冒号只作为句内标点，不产生“完全一致句子”边界。
- 换行只按空白处理，不把换行两侧的片段分别识别成句子。
- 不带句末标点的尾部文本不作为“完全一致句子”候选，避免把标题或未完成短语当成句子。

### 短表达过滤

- 比对键继续忽略空格、换行和标点差异。
- 句子归一化后，只保留汉字、字母和数字计算有效长度。
- 有效长度少于 8 的表达不参与完全一致句子匹配；有效长度恰好为 8 时可以参与。
- 因此“质量第一”“项目概况”“后续安排”等短表达不计入；“实施周期为30天”等达到长度要求的完整句子仍可计入。
- 对以“概况、目标、方案、措施、安排”等结尾、没有句内连接标点且没有明显谓语表达的标题式名词短语，即使长度达到 8，也不作为完整句子。
- 纯列表编号继续排除。

### 匹配范围

- 完整句子可以位于两个不同段落中，只要两边存在相同的完整句子即可归入对应重复组。
- 删除当前“整段文本完全相同则补算一条句子”的兜底逻辑，避免整段相同被错误降级为片段命中。
- 招标文件引用豁免和现有段落豁免继续生效。
- 句子字段结构保持不变，但历史结果数量可能因规则收紧而减少，需要重新对比后生成新结果。

## 实现边界

只修改 `client/electron/services/bidContentDuplicateService.cjs` 的句子切分和完全一致句子收集逻辑，以及对应的 `client/electron/services/bidContentDuplicateService.test.cjs`。结果字段 `exactSentenceCount`、`exactSentences` 和前端展示协议保持兼容。

## 验证标准

- 短词语、短语、短口号即使两边相同，也不会生成完全一致句子结果。
- 含逗号、分号或冒号的完整句子不会被拆成多个命中项。
- 句末标点、空格和换行差异不影响完整句子匹配。
- 现有小数、英文缩写、图片块和相似段落测试继续通过。
- 对一组包含短语、完整句子、句内标点和不同段落位置的模拟数据运行对比，结果只包含符合规则的完整句子。

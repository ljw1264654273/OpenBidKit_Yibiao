# 历史标书适配环节五：正文迁移设计

## 目标

在已确认的适配目录上，以历史标书正文为主体完成低扰动迁移。系统默认直接迁移，仅对项目地点与实施对象、工作量、工期与进度三类明确变化做局部改造，并在完成后执行一致性检查。其余改写、补写、扩写和缩写均由人工主动发起。

正文继续以 `technical_plan_outline_nodes.content` 为唯一权威。迁移元数据只记录来源、系统建议、人工选择、处理状态和一致性检查结果，不建立平行正文副本。

## 迁移策略

每个叶子章节具有系统建议方式和人工选择方式，最终执行方式以人工选择为准；未人工选择时使用系统建议。

- `direct`（直接迁移）：默认方式，完整复制可靠定位到的历史正文，不调用 AI。
- `local-rewrite`（局部改写）：仅用于已确认差异中涉及项目地点、实施对象、工作量、工期或进度的章节。模型返回可定位的精确替换项，Main 使用文本编辑工具应用；未命中、多命中或替换后仍有残留时标记为待复核，不得退化为整章重写。
- `rewrite`（定向改写）：只能由人工选择，允许结合历史正文、招标基线和人工要求重写当前章节；历史标书不存在正文时，同一方式承担按人工要求补充生成正文的职责。
- `review`（待人工处理）：不是处理方式，而是章节状态。历史正文无法可靠定位、新增章节尚未选择定向改写，或自动局部改造无法可靠应用时使用。未选择可执行方式的章节，批量迁移必须跳过且不得调用 AI；用户选择三种处理方式之一后才可继续，也可直接编辑保存正文。

系统不得因为目录重命名、目录移动、上级目录关联差异或一般性差异而自动选择定向改写。除上述三类局部变化外，所有能够可靠定位历史正文的章节都建议直接迁移。工作量始终取当前项目招标基线，不硬编码具体项目名称。

差异模型增加 `content_change_scope`：`location-target`、`workload`、`schedule` 或 `none`。只有 `decision=confirmed` 且 scope 为前三类的差异可以触发 `local-rewrite`；粗粒度的“名称地点替换”或“数据更新”类别本身不能触发自动改写。项目名称和一般数值变化保持直接迁移，再由一致性检查阻断并等待人工处理。

`ignored` 差异不参与自动局部改造。自动迁移不得执行扩写、缩写、篇幅调整或无明确依据的内容优化。

## 迁移方案与执行

正文迁移拆为方案和执行两个阶段：

1. 根据适配目录、历史目录、已确认差异和历史正文建立逐章迁移方案，不生成正文。方案保存目录版本、差异版本、招标基线版本、历史原文哈希、来源定位器和来源内容哈希。
2. 页面展示系统建议；用户可逐章选择处理方式，也可批量设为直接迁移。
3. 用户启动迁移后，后台任务按最终方式逐章执行并 checkpoint。
4. 修改下拉选择或要求只更新页面中的选择，不改正文和持久状态。点击“按此方式迁移本章”后先保存策略，再启动迁移；若正文曾人工保存，保存策略前必须确认覆盖，取消不产生任何写入。策略保存成功会标记该章 stale 并清除阶段确认、内容检查和终审结果。
5. 重新生成方案时，仅当 `node_id`、来源定位器和输入指纹兼容时保留 `manual_mode` 与人工要求，否则清除人工选择并重新建议。

首次方案中，能可靠定位正文的章节默认 `direct`；命中地点/对象、工作量或工期/进度 scope 时建议 `local-rewrite`；无法定位正文或新增章节的 `recommended_mode=null`、`status=review`，等待人工选择。直接迁移和局部改写只允许用于可靠定位到非空历史正文的章节；批量设为直接迁移只修改符合该条件的章节，并返回成功数和跳过数。

复用现有 Main/IPC 策略保存和迁移启动命令，由 Renderer 顺序调用；保存失败不得启动迁移，保存成功但启动失败时明确提示重试。`mode` 不独立持久化，而是由 `manual_mode ?? recommended_mode` 派生，空值表示未选择可执行方式。用户界面只展示 `direct`、`local-rewrite`、`rewrite` 三种处理方式；无可靠来源时展示禁用的选择提示。`review` 只作为待人工选择状态，不能作为下拉选项。

人工选择 `rewrite` 时必须填写 `manual_instruction`，用于限定整章定向改写目标；修改或清空该要求与修改策略相同，只使当前章 stale 并清除阶段确认、检查和终审结果。切换为其他策略时清空 `manual_instruction`。

## 一致性检查

每章迁移或人工保存后立即执行确定性章节检查；全部迁移或人工编辑完成后，由用户通过“运行一致性检查”明确启动独立受管后台任务 `historical-adaptation-content-check`。保存正文只把全量检查标记为 stale，不自动启动任务，避免连续编辑时反复锁定页面。检查至少覆盖：

- 旧项目名称、旧地点、旧行政层级和旧实施对象残留。
- 工作量与当前招标基线冲突或仍引用历史工作量。
- 工期、节点日期、阶段顺序和进度安排与当前基线冲突。
- 同一事实在不同章节中出现互相矛盾的表述。
- 正文为空、包含 `【待核实】` / `【待补充】` 或迁移任务失败。

确定性检查负责旧值/阻断词残留、空正文和待核实占位符；语义检查结合当前招标基线检查工作量、工期进度和跨章节事实冲突。语义检查只生成结构化 findings，不直接修改正文。

内容检查状态持久化到 `historical_adaptation_content_check_json`，包含 `status`、`findings`、`checked_content_hash`、`checked_inputs_hash` 和 `checked_at`；SQLite migration 与 `sql/workspace_schema.sql` 同步更新。正文、迁移策略、目录、差异或基线发生变化后立即将检查标记为 stale。阶段确认只做同步快照校验：检查必须成功、哈希与当前内容及输入一致且没有 blocker。

finding 最小结构为 `id`、`code`、`category`、`severity`、`blocking`、`node_ids`、`message` 和 `evidence`。`category` 至少覆盖 residual、workload、schedule、cross-chapter、placeholder、empty 和 task；跨章节问题保存全部相关节点，全局问题允许空节点数组。确定性错误以及语义检查判定为明确冲突的问题设置 `blocking=true`；建议性提示不阻断。`firstNodeId` 按目录顺序从阻断 finding 的 `node_ids` 中选择，纯全局问题不自动定位章节。语义检查通过受管任务的 scoped `aiService` 和结构化 JSON Schema 执行；模型请求、解析或校验失败时检查状态为 error，并阻断阶段确认。

可确定的旧值残留、正文为空、任务失败、未处理的 `review`、待核实占位符及明确的基线冲突属于阶段阻断问题。检查失败时保留已生成正文并列出相关章节，不静默修改为整章重写。

## 人工扩写与缩写

第五步正文编辑器复用现有 AI 候选编辑流程，新增明确的“扩写”和“缩写”操作：

- 有文本选区时，只处理选中文字。
- 无文本选区时，处理当前整章正文。
- AI 只返回候选；用户点击“应用到草稿”后仍需保存，才写入权威正文。
- 应用候选前校验正文快照，正文已变化时要求重新生成，避免覆盖新编辑。候选应用只改变 Renderer 草稿；只有保存草稿才清除阶段确认、内容检查和终审结果。
- 选区与内联图片标记、图片 Markdown 或 Mermaid 代码块相交时拒绝处理并要求重新选择。整章扩写或缩写把这些受保护内容替换为不可变占位符，模型返回后必须原样还原并校验；占位符缺失、重复或乱序时拒绝候选，避免丢图或破坏图表。
- 扩写和缩写永远不进入自动迁移任务，也不改变章节迁移方式。

人工定向改写（包括无历史正文时的补充生成）由用户明确选择后执行，不由一致性检查自动触发。

## 状态模型

`historical_adaptation_content_items_json` 逐叶子章节保存：

- `node_id`、来源路径和来源摘要。
- 可空的 `recommended_mode`、可选的 `manual_mode`；均只允许三种方式，最终方式由两者派生。
- 可选的 `manual_instruction`、方案输入指纹、来源定位器、来源内容哈希、处理状态、正文来源、原因、关联差异 ID、阻断词、残留项和更新时间。

章节状态枚举为 `idle | running | success | review | stale | error`。正文来源枚举为 `migrated | local-rewrite | ai-rewrite | supplement | manual`。保存人工正文时设置 `content_origin=manual` 并立即运行确定性章节检查：检查通过则状态变为 `success`，存在确定性阻断则为 `review`；因此人工正文可以直接解决原有 `review` 或 `error`，无需再调用 AI。只有策略或人工要求变化才把已有结果设为 stale。

旧记录升级不得把历史自动策略变成新的人工授权：legacy `direct` 可保留；legacy 自动 `supplement` 或 `rewrite` 转为空推荐并标记 stale，再按来源和 scope 重建建议。旧 `recommended_mode=review` 转为 null；旧人工 `supplement` 有非空要求时合并为 `rewrite`，无要求时清除策略并标记 review。旧正文和来源值继续兼容保留，新定向改写均写入 `content_origin=ai-rewrite`。旧 `confirmed_at` 仅兼容读取。

不再使用逐章 `confirmed_at` 作为阶段门禁。`historical_adaptation_content_confirmed_at` 仅表示用户已对当前全部成功结果执行“确认本阶段”。旧数据中的逐章确认时间可兼容读取，但不再要求或展示。

`HistoricalAdaptationContentCheckState` 和 `historicalAdaptationContentCheckTask` 加入 `TechnicalPlanState`；后者使用任务类型 `historical-adaptation-content-check`。页面卸载不取消迁移或检查任务。应用重启时，活动的迁移任务按既有规则保留已完成章节并恢复为可重试错误；活动的检查任务恢复为 error，检查快照保持 stale，未完成 findings 不作为有效结果。检查任务支持事件回放、显式重试和取消后等待 settled。

任务持久化本次目标节点集合。异常恢复时将仍在运行的节点转为 error，成功节点保持不变；默认“重试未完成章节”只处理非成功或 stale 节点，“重新迁移全部”是独立的明确操作。局部改写使用 `applyTextEdits()` 在全部替换项唯一命中后一次性提交；任一替换失败则一个也不应用，保留直接迁移正文并将该章标记为 `review`。

## 页面交互

环节五保持紧凑三栏工作台：

- 左侧为适配目录、章节状态和批量处理方式入口。
- 中间展示历史来源、系统建议、迁移方式、原因和关联差异；定向改写显示必填要求，选择尚未应用时明确提示，以唯一“按此方式迁移本章”执行。批量执行不能忽略当前未应用的选择。
- 右侧为 Markdown 编辑/预览、人工扩写/缩写和“保存人工修改”。

页面提供“运行一致性检查”操作并展示检查状态和问题数量。检查 stale 或 error 时，“确认本阶段”提示先完成检查，不在同步 Store 方法中启动后台任务。

删除“确认当前章节”按钮和“已确认章节数”。“确认本阶段”是全有或全无的事务：当前全部叶子必须有迁移记录、正文非空、状态成功、无活动任务、内容检查快照最新且没有 blocker；成功后只写项目级阶段时间戳，不写逐章确认。失败时 readiness API 返回 `{ ready, blockingCount, firstNodeId, findings }`，Renderer 显示问题数量并定位首个问题章节。环节五确认后进入环节六终审。

环节六终审同步取消逐章 `confirmed_at` 门禁，改为检查当前全部叶子有迁移记录、状态成功、正文非空、内容检查快照有效且环节五阶段时间存在。旧 `confirmed_at` 只兼容读取，不参与 UI、门禁或新写入。

## 门禁与失效

建立方案前检查项目类型、完整招标基线、差异全部处理、适配目录已确认、历史原文可读且目录非空。正文迁移或内容检查处于 `queued`、`running`、`pausing` 或 `paused` 时，禁止修改策略和正文。

保存章节策略或 `manual_instruction` 时将当前章设为 stale；保存人工正文时立即按确定性检查设为 success 或 review；重新迁移时按 running 到 success、review 或 error 转换。三者都只清除项目级阶段确认、全量检查快照和终审结果。修改上游差异或目录则沿用全量下游失效规则，并作为活动任务门禁的例外入口：必须先通过 `taskService` 取消相关任务并等待 runner settled，再在事务中清空下游状态。仅把扩写/缩写候选应用到未保存草稿不清除持久状态。

## 验证

- Runner 单元测试覆盖默认直迁、三类自动局改、人工定向改写、人工补写、局部替换失败和人工策略保留。
- Store 测试覆盖策略保存、批量直迁、单章失效、检查哈希防陈旧、无逐章确认的全有或全无阶段确认及结构化阻断结果。
- Renderer 测试覆盖策略选择、批量设置、移除逐章确认、扩写/缩写选区与整章入口。
- 环节六规则测试覆盖移除逐章确认依赖并改用阶段检查快照。
- 定向执行相关 CJS 测试、`node --check`、Electron native smoke 和 `npm run build`。
- 使用现有历史标书适配 UI 脚本回归桌面与窄屏布局、后台任务回放和阶段导航。

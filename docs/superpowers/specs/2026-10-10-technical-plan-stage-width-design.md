# 技术方案步骤条宽度与页面背景调整设计

## 目标

“新建标书”和“方案扩写”工作流都只有五个步骤。本次让两个入口保持一致：五个步骤在可用宽度内等分铺满，步骤卡的高度、字号、强调线、背景与圆角采用“以标写标”的视觉样式，主体区域使用统一浅色页面背景。

## 方案

- 保留 `TechnicalPlanStageNavigation` 的结构、状态样式和交互，不按 `workflowKind` 分叉布局。
- 两个入口共用的 `.technical-workbench-global-scroll` 使用 `var(--yb-page-bg, #f7f9fc)` 作为主体背景，覆盖壳层装饰渐变。
- 与“以标写标”一致，`.content-shell` 在技术方案全局滚动页保留上下 `28px`、左右 `36px` 外层内边距，使整块白色步骤面板和浅色工作区不贴侧栏或窗口边缘；该外层留白继续透出应用默认背景。
- 桌面宽度下把步骤网格定义为五列，五个步骤等分铺满步骤栏可用宽度。
- 步骤卡复用“以标写标”的紧凑视觉参数：`54px` 最小高度、紧凑字号和内边距、小圆角，以及当前步骤顶部蓝色强调线。
- 步骤面板保留桌面左右 `36px` 内边距，使首张卡与侧栏/折叠按钮之间有明确间隔；`900px` 以下缩为 `18px`。
- `900px` 以下继续使用现有五列最小宽度和横向滚动规则，避免窄屏卡片进一步缩小。
- 不修改步骤文案、状态计算或导航行为。

## 验证

- 先更新工作流布局定向断言并观察其因五等分参考样式尚未实现而失败，再实现最小改动使其通过。断言覆盖共用根容器背景、桌面五等分卡片样式和窄屏五列滚动规则。
- 运行完整的工作流布局定向测试，确认步骤导航结构和状态协议未变化。
- 运行 `npm run build`，确认 TypeScript 与 Vite 构建通过。
- 启动客户端，分别打开“新建标书”和“方案扩写”：桌面宽度下五张步骤卡等分铺满且视觉与“以标写标”一致，主体背景为统一浅色；不超过 `900px` 时步骤条无截断且仍可横向滚动。

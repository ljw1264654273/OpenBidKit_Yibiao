# 新建标书步骤条宽度调整设计

## 目标

新建标书工作流在宽屏下只有五个步骤，现有等分布局使单个步骤卡片明显宽于“以标写标”的六步布局。本次仅收紧步骤条的横向占用，使单步视觉密度接近“以标写标”。

## 方案

- 保留 `TechnicalPlanStageNavigation` 的结构、状态样式、交互和五列布局。
- 为 `workflowKind="technical-plan"` 的页面根节点增加专属修饰类，避免影响共用壳层的“方案扩写”入口。
- 在该专属作用域内为 `.technical-plan-stages` 设置 `width: 100%`、`max-width: 1560px` 和 `margin-inline: auto`。
- 容器宽度大于 `1560px` 时步骤条固定在 `1560px` 内并居中；容器宽度不超过 `1560px` 时填满可用宽度；`900px` 以下继续沿用现有横向滚动规则。
- 不修改步骤卡片高度、内边距、字号、文案、状态计算或导航行为。

## 验证

- 先新增工作流布局定向断言并观察其因专属类及宽度规则尚未实现而失败，再实现最小改动使其通过。断言覆盖专属根类、`max-width: 1560px` 和 `margin-inline: auto`，同时确认“方案扩写”不会获得该修饰类。
- 运行完整的工作流布局定向测试，确认步骤导航结构和状态协议未变化。
- 运行 `npm run build`，确认 TypeScript 与 Vite 构建通过。
- 启动客户端，分别检查宽度大于 `1560px`、不超过 `1560px` 且大于 `900px`、不超过 `900px` 三档：宽屏步骤条上限为 `1560px` 且居中，普通宽度填满可用区域，窄屏无截断且仍可横向滚动；“方案扩写”布局不变。

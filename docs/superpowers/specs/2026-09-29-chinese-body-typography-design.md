# 中文正文层级与 Word 排版规范化设计

## 目标

统一技术方案正文的中文排版，使默认正文层级按“一、”“（一）”“1．”“（1）”显示，编号与标题首字之间不出现空格、制表符或额外间距；清理中文正文中的异常空格和软换行，避免结束标点因前置空白被推到下一视觉行行首。

## 已定位原因

- Word 正文层级已经配置了四级编号样式，但编号配置使用 `LevelSuffix.TAB`，会在编号后生成制表符。
- 正文保存规范化会在加粗引导标题和后续正文之间主动插入一个半角空格；两端对齐时该空格可能被明显拉宽。
- 正文生成提示词已经要求嵌套 Markdown 列表，但历史正文、手工正文和不完全遵循提示词的模型输出仍可能包含扁平列表、手工中文序号或异常空格。
- Markdown 软换行会原样进入 Word 文本节点；当软换行位于右引号、句号等结束标点之前时，Word 会把它视为可断行空白，导致标点单独出现在下一视觉行行首。

## 设计

### 中文正文规范化

在 `client/electron/utils/chineseTypography.cjs` 提供纯函数，对普通 Markdown 正文进行保守清理：

- 删除中文字符、中文结束标点之间的半角或全角空格。
- 删除中文标点前的空格。
- 删除加粗中文小标题与紧随其后的中文正文之间的空格，同时保留 Markdown 标记。
- 删除同一普通中文段落内部、位于汉字或中文标点之间的 Markdown 软换行；保留空行分段和行尾双空格硬换行。
- 保留英文单词之间、数字与英文单位之间的必要空格。
- 跳过 fenced code、Markdown 表格、图片 Markdown、HTML 标签和属性、链接目标、行内代码和 Mermaid 内容。
- 保持幂等，重复执行结果不再变化。

新正文在 `normalizeLeafContentForSave()` 写入 SQLite 前规范化；Word 导出前再次规范化，为历史正文和手工正文提供兼容兜底，不批量改写已有 SQLite 数据。

### 正文层级编号

默认按 Markdown 嵌套层级映射以下编号样式，同时保留导出模板已有的正文层次可配置能力：

- 一级：`一、`
- 二级：`（一）`
- 三级：`1．`
- 四级：`（1）`

编号级别的 `suffix` 对有序列表改为 `LevelSuffix.NOTHING`，编号文字与标题首字直接连接；无序列表仍保留现有 tab 跟随行为。列表左侧位置仍由 Word 段落缩进控制，不通过空格或制表符对齐。

Markdown 源中的 `1. 标题` 必须保留语法要求的一个空格；删除的是 Word 最终编号的 suffix，不是 Markdown 列表标记后的语法空格。生成提示词继续要求使用嵌套 Markdown 有序列表，并说明最终显示编号由 Word 模板控制。保存规范化仍负责连续编号，不在无法确定语义层级时猜测父子关系。

`decimal-dot` 的 Word 显示字符改为全角句点 `．`，对应中文正文的 `1．` 样式；用户选择其他正文层次编号样式时仍按模板配置输出。

### 用户可见规则

更新导出格式页面的强制内容规则，明确正文层级编号、编号后无间距、中文正文空格和行首标点要求。规则说明与实际导出保持一致。

## 不在范围内

- 不修改 SQLite schema、IPC、Analytics 或菜单路由。
- 不批量改写已保存正文；旧正文只在导出时清理。
- 不删除英文语句中的正常空格。
- 不根据标题语义猜测无法从 Markdown 缩进确定的层级。

## 验收标准

- Word 有序列表编号 XML 使用 `nothing` suffix，不再生成编号后的 tab 或 space。
- 默认四级正文编号分别显示为“一、”“（一）”“1．”“（1）”。
- 中文小标题和正文之间没有可被两端对齐拉宽的真实空格。
- 中文标点前后不存在异常空格，英文和数字必要空格保持。
- 导出的正文文本节点不再含有位于右引号、句号等结束标点之前的空格或软换行。
- 新生成正文和旧正文导出均应用规则。
- 定向 Node 测试、Main 语法检查、`npm run build` 和一次真实 Word 导出视觉检查通过。

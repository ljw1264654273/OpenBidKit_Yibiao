# 第四步目录操作条布局调整设计

## 背景

历史标书适配流程的第四步“目录适配”中，适配后目录的操作按钮当前与栏目标题处于同一行。按钮数量较多时会挤压标题区域，并在较窄窗口中形成横向滚动，影响目录树的阅读路径。

## 目标

- 保留现有目录操作及其行为不变。
- 将目录级操作按钮从“适配后目录”标题行移到目录树下方。
- 让标题行只承担栏目识别和一级目录数量展示。
- 在窄窗口中允许操作条换行，避免标题区域横向滚动。

## 方案

调整 `AdaptationOutlinePage` 的 DOM 结构：

1. `适配后目录` 标题行仅保留标题和一级目录数量。
2. 目录树继续使用现有滚动容器，操作条放在该滚动容器之外，作为适配目录栏的独立底部区域；操作条不随目录树滚动，也不参与目录树的横向滚动。
3. 在目录树之后新增目录操作条，沿用现有按钮、禁用条件和事件处理：增加一级目录、增加子目录、上移、下移、全部展开、全部折叠、删除。
4. 同步调整适配目录栏的网格行结构为“标题 / 可滚动目录树 / 底部操作条”，并移除操作条的横向滚动策略；桌面端横向排列，较窄容器下在自身区域自动换行并保持可操作间距。

## 不在范围内

- 不改变任何目录编辑、排序、删除、展开/折叠或保存逻辑。
- 不调整右侧“变更依据”编辑区和底部“确认目录”区域。
- 不新增 IPC、持久化字段或埋点。

## 验证

- 使用 `cd client; npm run build` 验证 TypeScript 与 Vite 构建。
- 目视检查第四步：标题行不再出现操作按钮；按钮位于目录树下方且不随目录树滚动；窗口变窄时按钮仅在自身区域换行，不出现标题区或操作条横向滚动。

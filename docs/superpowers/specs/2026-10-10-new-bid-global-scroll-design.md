# 新建标书全流程全局滚动布局设计

## 背景

当前“新建标书”入口由 `BidProjectCreatePage` 挂载 `TechnicalPlanHome`，创建项目后继续使用技术方案工作流的 STEP 01 至 STEP 05。现有页面采用“外层锁定可用高度、步骤模块占满剩余空间、各步骤工作台内部滚动”的结构：

- `technical-workbench`、`technical-step-module` 和 `technical-step-content` 均限制高度并隐藏溢出；
- STEP 01 使用步骤内容区内的独立纵向滚动；
- STEP 02 至 STEP 05 的命令区和工作台固定在剩余高度内，工作台中的列表、预览和编辑器再分别滚动。

这种结构适合并排编辑，但页面标题、流程导航、命令区和多层滚动共同占用空间，用户不能沿一条连续滚动轴浏览完整页面。用户确认以“历史标书适配”页面为视觉参考，将新建标书五个主流程统一为“顶部流程卡 + 下方连续内容”的页面结构，并扩大可查看范围。

本次只调整 Renderer 布局、导航呈现和滚动边界，不修改 Electron Main、IPC、SQLite、AI 任务、持久化协议或 Analytics。

## 目标

1. STEP 01 至 STEP 05 使用统一的页面骨架、流程状态表达和内容间距。
2. 由新建标书页面根容器承担唯一页面级纵向滚动，不依赖 `body` 滚动。
3. 顶部五步流程卡在页面滚动时吸顶，始终可见。
4. 取消顶部通用“首页 / 上一步 / 下一步”导航，释放垂直空间并消除与流程卡的重复。
5. 每一步在内容底部提供与当前业务状态绑定的主动作；返回已完成步骤通过顶部流程卡完成。
6. 普通内容自然展开；目录树、任务列表、Markdown 预览、正文编辑器等专业工作台保留必要的面板内滚动。
7. 保留现有任务状态、错误处理、编辑保护、目录排序离开确认、导出条件及后台任务恢复行为。

## 范围

### 纳入

- `workflowKind="technical-plan"` 下的 STEP 01 至 STEP 05。
- 新建项目上传前状态，以及项目创建后进入技术方案工作流的状态。
- 顶部流程卡、项目上下文区、步骤内容容器、步骤底部业务动作区。
- STEP 01 上传和快速配置的自然纵向布局。
- STEP 02 文件解析、STEP 03 目录生成、STEP 04 事实设定、STEP 05 正文生成的工作台高度与滚动边界。
- 默认桌面窗口和窄窗口下的响应式行为。

### 共享页面影响

`TechnicalPlanHome` 同时承载 `existing-plan-expansion`。实现时必须为根容器增加明确的工作流修饰类，只在 `technical-plan` 工作流启用本设计的页面级滚动和新流程卡布局；已有方案扩写继续保持现有布局。由于步骤组件共享，仍需验证已有方案扩写未出现高度、滚动或操作回归。

### 不纳入

- 历史标书适配流程自身的页面改造。
- STEP 06“扩写改写”占位页。
- 侧边栏、菜单信息架构和应用壳层滚动规则。
- 后台任务、AI Prompt、模型配置、文件解析、Store、IPC 或数据库调整。
- 新增业务步骤、统计指标或持久化 UI 偏好。

## 页面结构

新建标书页面按以下顺序组成：

1. 吸顶流程区；
2. 远程知识异常提示（存在时）；
3. 项目上下文区；
4. 当前步骤命令区和主体工作台；
5. 当前步骤业务确认区。

页面根容器保持 `width: 100%`、`height: 100%`、`min-height: 0`，并设置 `overflow-y: auto`。`body` 和应用壳层继续 `overflow: hidden`。流程区使用 `position: sticky; top: 0`，其背景必须不透明，并设置足够的层级避免正文从下方透出。

项目上下文区显示当前项目名称、工作流说明、同源项目序号（存在时）以及“返回我的标书”。不再显示“首页 / 上一步 / 下一步”。“返回我的标书”继续走现有 `onSectionChange('bid-projects')`，不改变离开保护逻辑。

## 顶部流程卡

流程区固定展示五张等宽步骤卡：

1. 选择标书
2. 文件解析
3. 目录生成
4. 事实设定
5. 生成正文

每张卡包含两位编号、步骤名称和状态文案。状态使用现有业务数据推导，不新增持久化字段：

- `已完成`：步骤结果已满足进入下一阶段的条件；
- `当前步骤` 或更具体的 `待验收`：等于当前 `state.step`；
- `可开始`：前置条件已满足且该步骤可进入；
- `待开放`：前置条件尚未满足；
- 任务运行时可显示现有语义对应的 `解析中`、`生成中`、`调整中` 等状态。

实现时在 `TechnicalPlanHome` 内集中派生一份步骤展示模型，统一给流程卡、底部业务动作和目标步骤准入判断使用。该模型只组合现有的文件、任务、目录、事实和正文状态，不新增业务状态，也不复制 Main 持久化规则。`switchStep()` 继续作为实际切换入口，并以同一份准入结果阻止非相邻步骤跳转，避免流程卡和底部动作出现不同的可访问状态。

交互规则：

- 当前步骤卡可点击但不触发重复导航；
- 已完成和可开始的步骤卡可点击；
- 待开放步骤卡使用真实 `disabled`，同时保留清晰的状态文案；
- 切换步骤继续调用现有 `switchStep()`，必须保留目录排序离开确认、待填写事实定位和解析结果缺失定位等守卫；
- 不允许通过点击流程卡绕过当前已有的进入条件。

宽度不足时，流程卡保持可读的最小宽度并在流程区内横向滚动，不压缩中文标签、不缩小字号。页面仍只有一条纵向主滚动轴。

## 步骤内容与滚动边界

### STEP 01 选择标书

- 上传区、投标范围提示、快速配置和文件预览按正常文档流纵向排列。
- 移除步骤内容容器对该页面的固定高度和独立纵向滚动。
- Markdown 文件预览可以保留自身的最大高度和滚动，以免单份超长文件无限拉长页面。
- 上传、继续上传、删除、标段识别和快速配置行为保持不变。

### STEP 02 文件解析

- 命令区位于工作台上方，展示解析说明、进度、配置摘要和重新解析操作。
- 双栏工作台保留左侧解析项目列表和右侧解析结果。
- 工作台设置稳定的视口相关最小高度，使列表和结果拥有比当前更大的可视范围；列表和结果各自保留内部滚动。
- 工作台使用明确高度而非仅设置 `min-height`：桌面端共享基线为 `height: clamp(620px, calc(100dvh - 260px), 820px)`。页面高度不足时由根容器滚动到完整工作台和确认区，工作台内部列表与结果仍有确定高度可滚动。
- 工作台之外的页面标题、命令区和确认区随页面根容器滚动。

### STEP 03 目录生成

- 保留招标原文、目录、目录项详情三栏工作台及可拖动分隔逻辑。
- 保留三栏内部各自滚动、目录联动定位、窄容器标签切换和全屏查看。
- 工作台沿用共享视口高度基线，不将完整目录树或招标原文直接展开到页面文档流。
- 目录生成、一级目录确认、编辑、排序、知识引用和保存逻辑保持不变。

### STEP 04 事实设定

- 命令区、进度和统计位于双栏工作台上方。
- 左侧事实列表、右侧编辑/预览继续各自使用内部滚动。
- 工作台沿用共享视口高度基线；保存、AI 调整、待填写定位和编辑草稿行为保持不变。

### STEP 05 生成正文

- 命令区、任务进度、开发者统计和配图审核提示位于正文工作台上方。
- 左侧目录树和右侧正文阅读/编辑区域继续各自滚动。
- 正文工作台沿用共享视口高度基线，确保目录与正文面板具备确定的内部滚动高度。
- 暂停、继续、失败处理、图片审核、手工编辑和全屏预览行为保持不变。
- 页面底部业务动作区显示导出 Word，不再显示首页或上一步。

## 步骤业务动作区

每一步内容后方放置统一样式的状态与动作区。左侧说明当前是否满足进入下一环节的条件，右侧最多一个主动作：

| 步骤 | 主动作 | 可用条件 |
| --- | --- | --- |
| 选择标书 | 进入文件解析 | 沿用现有 `isNextDisabled` 对文件、原方案和快速配置的判断 |
| 文件解析 | 确认解析结果，进入目录生成 | 沿用标段选择、解析任务和必需解析项完整性判断 |
| 目录生成 | 确认目录，进入事实设定 | 目录、字数控制快照和最低层级快照有效 |
| 事实设定 | 确认事实设定，进入正文生成 | 全局事实已生成、无待填写且调整任务已结束 |
| 生成正文 | 导出 Word | 沿用当前正文、任务和导出状态判断 |

前四个进入动作继续复用 `switchStep()`，不得另写第二套状态更新或 IPC。导出继续打开现有 `WordExportDialog`。动作不可用时使用现有原因生成逻辑提供可操作提示，不新增通用“下一步”。

## 视觉规则

- 参考历史标书适配页的流程卡结构，但复用当前 `--yb-*` token 和新建标书现有克制表面。
- 内容面板圆角不超过 8px，常规控件圆角不超过 6px。
- 完成态使用成功色，当前态使用主色，未开放态使用中性弱化色；状态不能仅依赖颜色，必须同时显示文字。
- 流程区、页面标题、命令区和工作台对齐同一组左右边缘。
- 不引入 Tailwind、第三方 UI 库、新图标体系或装饰性渐变背景。
- 不增加与业务无关的说明卡、统计卡或占位区域。

## 状态与错误处理

- 页面滚动位置只属于当前 Renderer 生命周期，不持久化。
- 切换步骤后将页面根滚动位置重置到顶部，避免新步骤从中部开始显示。
- 后台任务事件、快照恢复和页面卸载不取消任务的规则保持不变。
- 任务错误继续显示在对应命令区或工作台内；错误不得被吸顶流程区遮挡。
- 弹窗、Popover、全屏 Markdown 和 Word 导出对话框继续使用现有层级，不受 sticky 流程区覆盖。
- 远程知识异常入口继续可见，并放在流程区下方的页面文档流中。

### 手动验证

1. 新项目上传前与上传后均只有一条页面级纵向主滚动轴；

建议至少检查 `1440x920`、`1040x720`，并覆盖侧边栏展开和收起状态。

## 验收标准

- 新建标书五步采用同一套“吸顶流程卡 + 连续页面内容 + 底部业务动作”骨架。
- 页面标题和普通内容随一条页面级滚动轴滚动，`body` 仍不滚动。
- 专业工作台获得更大的稳定可视范围，同时保留必要的局部滚动。
- 页面中不再出现通用“首页 / 上一步 / 下一步”。
- 顶部流程卡可以返回已完成步骤，但不能进入未开放步骤。
- 所有原有业务流程、后台任务、持久化、错误处理和导出规则保持不变。
- 定向测试通过，`npm run build` 退出码为 0，手动窗口验证无重叠、裁切或不可达操作。

## 非目标

- 不重做步骤内部业务功能或信息模型。
- 不改变流程完成条件、任务调度或数据失效规则。
- 不统一改造历史标书适配、可行性报告或其他菜单页面。
- 不增加移动端专用交互；只保证窄桌面窗口下可用。

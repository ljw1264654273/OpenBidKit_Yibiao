# 历史空正文章节定向改写提纲设计

## 目标

当第五步某章节的历史标题已定位但正文为空时，用户选择“定向改写”后，系统自动复用 Main 侧推荐提纲任务生成 3—6 条可校核的写作要点，并回填到“定向改写要求”输入框。用户可修改提纲后再执行本章迁移。

## 行为边界

- 仅在历史来源已定位、且来源读取明确返回“历史原文为空”，且用户切换到“定向改写”时触发；来源快照缺失、定位不唯一或哈希不匹配不得触发该流程。
- 生成请求使用已有招标基线、章节说明和已确认差异；不生成正文，不改变章节正文内容。
- 请求必须限定为当前章节，不得因为一次指定章节请求而处理其他待迁移章节。
- 生成期间输入框和迁移按钮保持不可执行，展示“正在生成推荐提纲”。
- 生成成功后提纲进入可编辑输入框；生成失败保留错误提示，用户仍可手工填写要求并继续迁移。
- 新增目录章节的既有推荐提纲逻辑、真实来源哈希不匹配的错误提示均保持不变。

## 实现方向

前端在迁移方式变为“定向改写”且无当前要求、无历史正文时，调用现有 `onPreparePlan` 任务并限定 `includeNodeId` 与 `recommendationsOnly`。Main 任务只对这个指定章节生成推荐提纲，即使其推荐模式原本为空；生成结果通过现有技术方案状态事件回写 `recommended_instruction`。页面将该推荐内容作为定向改写要求的初始值，后续人工编辑仍走现有策略保存接口。请求失败时不阻断手工填写与后续迁移。

## 验证

- Main 侧增加回归测试，覆盖空正文章节在指定推荐请求下生成提纲且不生成正文。
- Renderer 侧增加交互测试或纯函数测试，覆盖切换定向改写触发一次指定章节请求、成功回填、失败可手工继续；Main 测试覆盖指定节点隔离。
- 执行相关 Node 测试、`npm run build`、`npm run smoke:electron-native`，并重启开发窗口验收。

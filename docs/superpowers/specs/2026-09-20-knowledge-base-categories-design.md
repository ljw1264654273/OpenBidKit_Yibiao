# 知识库分类与一级入口设计

## 目标

将当前单一的本地文档知识库扩展为六个固定系统分类，并把本地知识库、远程知识库和图片知识库统一提升为一级菜单。现有文档全部迁移到“文档知识库”，所有当前使用本地知识库的流程均可跨六类本地库选择，文档可在本地库之间移动且保留已有引用和处理结果。

## 已确认的产品规则

一级入口固定为：

- 文档知识库
- 国标知识库
- 省标知识库
- 市标知识库
- 行业标知识库
- 企业知识库
- 远程知识库
- 图片知识库

“知识库”旧父级菜单取消。六类本地知识库是固定系统分类，用户不能新增、删除或重命名分类，只能在分类下管理文件夹和文档。图片知识库仍保留当前开发中状态。远程知识库只复用现有浏览、分页、整库选择和文档选择能力，暂不提供远程内容管理。

六类本地知识库的导航 ID 与数据库分类 ID 一一对应：

| 导航 ID | 数据库分类 ID | 中文名称 |
| --- | --- | --- |
| `document-knowledge-base` | `document` | 文档知识库 |
| `national-standard-knowledge-base` | `national-standard` | 国标知识库 |
| `provincial-standard-knowledge-base` | `provincial-standard` | 省标知识库 |
| `municipal-standard-knowledge-base` | `municipal-standard` | 市标知识库 |
| `industry-standard-knowledge-base` | `industry-standard` | 行业标知识库 |
| `enterprise-knowledge-base` | `enterprise` | 企业知识库 |

远程和图片一级入口分别使用 `remote-knowledge-base`、`image-knowledge-base`。旧 `knowledge-base`、旧 `document-knowledge-base` 和旧 `image-knowledge-base` 状态都保留入口兼容，其中旧图片状态在新菜单中仍映射到图片知识库并显示开发中提示。

六类本地库共用当前文档知识库的表、文件处理链路、任务事件和知识条目逻辑。文件夹归属于一个本地库，文档通过文件夹间接归属。文档支持跨库移动，操作目标为“目标知识库下的目标文件夹”；文件夹本身不能跨库移动。移动不改变 `document_id`，保留原始文件、Markdown、解析结果、知识条目、匹配结果和历史直接文档引用。处理中的文档继续禁止移动。

目录节点关联具体文档时使用稳定 `document_id`，文档移动后关联继续有效。目录节点关联文件夹时按生成时的当前文件夹内容动态解析，文档离开原文件夹后不再通过该文件夹关联被使用。旧 `knowledge-base`、旧 `document-knowledge-base` 入口和历史导航状态统一映射到“文档知识库”。

## 数据模型与迁移

在 `knowledge_folders` 增加固定分类字段 `knowledge_base_id`。采用稳定内部标识：

```text
document
national-standard
provincial-standard
municipal-standard
industry-standard
enterprise
```

中文名称只属于 UI 配置，不写入业务引用。已有数据库通过一次幂等 migration 将所有现有文件夹归入 `document`。不复制六套知识库表，也不修改文档、条目、Block、报告和步骤表的主键关系。现有文档物理目录继续由现有 folder/document 路径管理，跨文件夹移动沿用现有文件搬迁和回滚逻辑。

Store 的索引接口支持按分类过滤，也能返回带分类信息的全量索引，供跨库选择器统一展示。创建文件夹必须携带分类；为保持旧调用兼容，缺省分类按 `document` 处理。文档移动根据目标文件夹自动完成分类切换，不新增冗余分类字段到文档表。

## Renderer 与 IPC

知识库页面接收当前固定分类 ID，加载和创建文件夹时传递分类 ID；页面标题、空状态和埋点显示当前分类名称。文档列表只展示当前分类的文件夹，跨库移动时提供目标分类和目标文件夹选择，文件夹拖拽仍只在当前分类内排序。技术方案、已有方案扩写、可研目录和目录节点选择器读取全量本地索引，并按分类分组展示，保留跨库多选能力。

新增“远程知识库”页面包装现有 `RemoteKnowledgePicker`，复用其远程加载、分页、选择和失败重试逻辑；远程页面的临时选择状态只在当前页面会话中存在，离开页面后不写入本地知识库，也不新增远程管理 IPC。技术方案等已有流程仍独立保存自己的远程选择配置。

导航需同步 `navigation.ts`、`menuConfig.ts`、`AppRouter.tsx`、`Sidebar.tsx` 和 Analytics Dashboard 的中文路由名。旧父级和旧二级 SectionId 保留类型兼容或在入口处归一化，不再出现在新菜单树中。

## 业务影响

本地知识库索引中增加分类字段后，技术方案目录生成、全局事实、正文规划/生成、已有方案扩写和可行性研究报告继续使用稳定文档 ID，因此历史引用无需改写。所有会显示文件夹或文档的选择器都显示“知识库分类 / 文件夹 / 文档”的上下文，避免同名内容混淆。文档移动后，直接文档引用保持可用，文件夹关联按当前内容动态生效。

## 错误与兼容

- 缺少分类或遇到旧数据时默认归入 `document`。
- 不允许将文档移动到不存在的目标文件夹。
- 文档正在处理时继续返回现有不可移动错误。
- 数据库 migration 必须幂等，并同步根目录 `sql/workspace_schema.sql`。
- 现有知识库事件继续推送完整文档，移动后页面通过重新加载索引刷新文件夹和分类关系。
- 不改变 Analytics 的采集能力，只补充新一级入口的页面名称映射。

## 验证范围

需要覆盖数据库升级和旧数据归类、六类本地库的文件夹与文档操作、跨库移动及处理状态限制、历史文档引用、技术方案/可研跨库选择、远程知识库页面复用、旧入口兼容和一级菜单导航。最低执行 `node --check`、`npm run build`、知识库相关定向 Node tests、`npm run smoke:electron-native`，并启动开发环境手动验证主菜单、迁移后的数据和跨库移动链路。

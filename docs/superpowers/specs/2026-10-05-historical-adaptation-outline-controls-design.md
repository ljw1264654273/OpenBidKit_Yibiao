# 历史标书适配目录控制设计

## 背景

环节四“目录适配”目前已经能够展示原目录和适配后目录，并支持编辑、增删和排序，但目录树没有折叠控制，也没有把“是否直接沿用历史正文”的决定明确绑定到目录节点。用户需要在目录层面快速识别变化、审核系统新增章节，并逐节决定后续正文是否直接沿用历史标书原文。

## 目标与边界

目标：

- 适配后目录支持按节点折叠/展开，并提供全部展开、全部折叠操作。
- 系统根据招标基线和已确认差异，先生成历史目录缺失内容的新增目录候选；人工再审核、编辑或删除。
- 历史已有目录默认选择“沿用历史原文”；新增目录默认不沿用原文，进入后续人工处理/补写流程。
- 每个节点可以单独切换正文处理选择，选择可持久化、可重启恢复，并随目录重编号、删除和排序保持正确节点关联。
- 新增、标题调整、位置调整、内容调整和沿用节点在目录树中有明确且可访问的视觉状态。

不在本次范围内：

- 不改变差异确认、历史原文索引、正文编辑器和一致性检查的业务规则。
- 不新增独立的并行目录或正文 JSON 存储；继续以 SQLite 中的技术方案状态和适配目录变更记录为权威。
- 不改动 Analytics 埋点协议。

## 现有流程与决定

目录适配任务会读取历史标书目录、已确认差异和完整招标基线。AI 任务允许在历史目录没有覆盖、但招标基线明确要求的地方生成 `change_type=added` 的候选节点，并记录原因和关联差异。任务完成后，人工在适配目录中审核候选；人工仍可补充系统未识别的目录。

历史已有目录（`unchanged`、`renamed`、`updated`、`moved`）默认沿用历史正文，前提是节点存在可定位的历史来源。新增目录默认不沿用原文，因为不存在对应历史章节。没有可靠历史来源的节点不能显示为可直接复用，并需要进入待人工处理状态。

## 数据设计

在既有 `HistoricalAdaptationOutlineChange` / `historical_adaptation_outline_changes_json` 记录上增加可选字段：

```ts
reuse_original?: boolean
```

字段语义：

- `true`：正文迁移阶段将本节点强制按 `direct` 处理，完整复制对应历史章节正文，不调用 AI。
- `false`：明确关闭直接复用。正文迁移阶段不得回退到 `recommended_mode=direct`；节点必须进入“按适配规则处理”路径。实现上优先通过现有 `manual_mode` 写入一个非 `direct` 的处理方式（历史来源可用时默认 `local-rewrite`，无来源时默认 `rewrite` 并要求人工说明），或增加等价的显式 opt-out 判定，但必须保证用户关闭复用后不会直接复制原文。
- 缺失：按兼容逻辑推断，已有历史目录视为 `true`，新增目录视为 `false`；用户第一次保存目录或切换该选项后写入显式值。

目录任务生成的变更记录和人工目录操作都保留该字段。目录重编号时沿用现有 `idMap` 映射；删除节点时删除其对应记录；排序只重映射节点 ID，不改变字段值。现有规范化函数需要保留该字段，避免保存/重启时丢失。

## 交互设计

### 目录树

- 适配后目录的每个分支节点有折叠箭头；叶子节点显示不可展开状态。
- 目录面板工具栏提供“全部展开”和“全部折叠”。折叠状态属于页面 UI 状态，不写入业务数据库。
- 节点行保留点击选中行为；选中节点后右侧详情显示编辑、删除和正文处理控制。
- 编辑、删除使用现有操作链路和 Toast；删除父节点按现有语义连同子节点删除，并保留适配删除记录。

### 状态标识

节点行使用颜色、状态徽标和非颜色文本共同表达状态，保证色觉可访问：

- 状态优先级为“新增 > 调整 > 沿用”：
  - 蓝色：新增目录候选，默认不沿用历史原文。
  - 琥珀色：标题、位置或内容发生适配调整。
  - 绿色：历史目录节点，当前选择沿用历史原文。
- 已删除目录继续在原目录列的“已删除目录”区域展示。

节点详情显示状态文字，例如“沿用历史原文”“新增目录，待补写”“目录已调整”，并显示原路径、变更原因和关联差异。

### 正文处理选择

在适配目录详情中增加单节点选择控件：

- “沿用历史原文并应用内容调整”（历史来源可用时默认选中，以历史正文为底稿并执行已确认的内容调整）。
- “按适配规则处理”（新增目录或用户明确关闭复用时使用）。

新增目录默认选中第二项且提示“原目录没有对应章节，后续需要补写或人工指定处理方式”。没有可靠来源的已有节点禁用第一项并显示原因。

切换选择立即保存目录变更记录；保存期间禁用重复操作。保存失败通过 Toast 告知用户，页面保留当前选择，避免静默丢失。

## 数据流与正文迁移联动

1. 目录适配任务生成 `outlineData`、原目录快照和变更记录。
2. Renderer 展示树并按变更记录计算默认复用状态；人工修改标题、增删节点或切换复用状态时调用 `saveHistoricalAdaptationOutline`。
3. Main Store 在同一事务中保存目录、变更记录和适配正文状态失效信息；不在 Renderer 复制正文清理规则。
4. 环节五建立/更新迁移方案时，正文任务读取节点对应变更记录：
   - `reuse_original=true` 且历史来源可用时，以历史正文为底稿；有可自动应用的内容调整时使用 `local-rewrite`，没有时使用 `direct`。
   - `reuse_original=false` 时，沿用现有推荐方式、人工处理方式和无来源待处理规则。
   - `change_type=added` 默认 `reuse_original=false`，不得把其他章节正文静默当作原文复制。
5. 已保存的人工正文仍受现有保护规则约束；改变目录复用选择会使适配正文计划失效，但不会删除用户已保存的人工正文。

## 错误与边界

- 目录节点不存在对应变更记录时按兼容默认值推断，不阻塞旧工作区加载。
- 历史来源读取失败时，复用控件禁用并提示重新建立/读取历史来源；正文任务不得伪造“直接迁移成功”。
- 目录正在生成、正文任务运行/暂停或其他现有锁定状态下，沿用现有规则禁止目录变更。
- 所有成功、失败和普通提示使用 `useToast()`，确认类交互使用现有共享 Dialog，不使用 `alert`、`confirm` 或 `prompt`。

## 验证方案

- Renderer：`cd client; npm run build`。
- Main Store/任务：对修改的 `.cjs` 执行 `node --check`，定向运行历史适配目录和正文迁移相关 `node --test`，并运行 `npm run smoke:electron-native`。
- 手工验证：生成适配目录后检查新增候选、颜色和折叠；切换一节复用状态并刷新/重启恢复；确认新增章节不复用原文、已有章节默认以历史原文为底稿并应用已确认内容调整；检查编辑、删除、排序后的选择仍绑定正确节点。

# 技术方案工作流页面布局优化设计

## 背景

技术方案工作流的 STEP 03 已改为招标原文、目录、目录项详情三栏联动工作台。其余步骤不能机械复用三栏结构，应根据每一步的主任务和需要同时对照的信息数量选择布局。

本次仅优化现有 Renderer 页面结构、视觉层级和滚动行为，不修改 Electron Main 后台任务、IPC、SQLite 数据结构或 AI 生成协议。已有方案扩写入口与技术方案入口继续共用同一套 STEP 01 至 STEP 05 页面。

## 目标

1. 压缩 STEP 01、02、04、05 顶部标题、统计和操作区域，让主体工作区获得更多高度。
2. STEP 02、03、04、05 等现有具备任务进度数据的页面保持进度条可见；运行日志、错误说明等过程数据默认折叠并可展开。STEP 01 和尚未接入任务的 STEP 06 不虚构百分比。
3. 每一步按实际任务选择单区、双栏或三栏，不统一套用三分屏。
4. 保留底部 `FloatingToolbar` 覆盖式悬浮设计，不为其额外预留大段空白。
5. 页面根容器保持 `height: 100%`、`min-height: 0`，长内容只在内部面板滚动。
6. 保留 STEP 03 已实现的三栏联动和招标原文全屏滚动修复。

## 页面方案

### STEP 01 选择标书：单主区

- 顶部上传区压缩为紧凑资料区，保留解析方式、上传、继续上传、替换和删除等现有行为。
- 多份招标文件使用紧凑文件列表展示；已有方案扩写入口继续显示原方案上传行。
- 解析后的 Markdown 正文预览占据页面主要高度。
- 多文件和原方案切换继续使用现有标签，不新增文件角色或标段配置。

### STEP 02 招标文件解析：双栏

- 左侧为解析项目列表和紧凑进度区。
- 右侧为当前解析项结果，继续支持 JSON 表格、Markdown、复制、全屏和单项重试。
- 进度条常显，日志说明默认折叠；失败提示在展开区保留。
- 解析配置继续放在现有弹窗中，不增加第三个配置栏。

### STEP 03 目录生成：三栏

- 保持已确认并实现的招标原文、目录、目录项详情三栏工作台。
- 保持窄容器下标签切换、进度浮层和目录联动定位。
- 招标原文全屏使用共享 Markdown 滚动容器样式。

### STEP 04 全局事实设定：双栏

- 左侧为事实大项列表和紧凑进度区。
- 右侧只显示一个主工作面：编辑或预览，通过明确的“预览/编辑”按钮切换。
- 编辑模式保留标题输入和 Markdown 编辑器；预览模式保留 Markdown 渲染与全屏查看。
- 默认进入编辑模式；用户切换事实大项后保留当前编辑/预览模式。模式切换只读取当前标题和正文草稿，不保存、不重置草稿。
- 复制、删除、保存、AI 调整和生成配置行为不变。
- 不增加原文证据栏，因为当前数据模型没有事实级原文定位关系。

### STEP 05 正文生成：双栏

- 左侧为目录树、当前总进度和小节状态。
- 右侧为选中小节正文，继续支持 Markdown 阅读、编辑、预览、保存、重新生成和全屏。
- 当前阶段进度条常显，过程说明默认折叠；组件直接透传现有编排、原方案还原、字数调整、内容矫正、配图等阶段的标签、数值、计数、颜色和运行状态，不重新计算一个新的总体百分比。
- 暂停中、已暂停、失败待决策状态保持原有含义；“重试失败小节”和“继续后续流程”等现有入口必须继续可见可用。
- 不增加独立生成队列栏，目录状态已承担队列导航作用。
- 开发者配图统计保持独立紧凑行，只在开发者模式显示。

### STEP 06 扩写改写：现状占位优化

- 当前代码尚未接入独立扩写引擎，本次不新增虚假的原文对照、改写策略或保存流程。
- 仅将现有占位内容调整为与工作流一致的紧凑空状态，明确后续能力尚未接入。

## 共享组件与样式

- 在 `technical-plan` feature 内增加可复用的紧凑任务进度组件，供 STEP 02、04、05 使用。
- 组件负责常显进度条、展开/折叠过程说明和无障碍状态；各页面继续拥有业务状态与错误文案。
- 页面继续使用全局 CSS 和现有 `--yb-*` token，不引入 Tailwind 或新的组件库。
- STEP 02、04、05 的双栏工作区使用容器查询。工作区可用宽度不小于 `760px` 时同时显示双栏；低于 `760px` 时显示两个等宽工作区标签，一次只显示一个面板。
- 窄容器下 STEP 02 默认显示“解析项目”，选择任务后切到“解析结果”；STEP 04 默认显示“事实大项”，选择大项后切到“事实内容”；STEP 05 默认显示“标书目录”，选择小节后切到“正文内容”。用户可以随时通过标签返回导航面板。
- 每个可见面板独立占满剩余高度并在内部滚动。标签和面板 DOM 顺序保持“导航在前、内容在后”，关键操作不得被裁切。

## 状态与错误处理

- 折叠状态仅为 Renderer 临时 UI 状态，不持久化到业务数据库。
- 任务失败时进度条和失败状态仍可见，展开后显示原错误和重试说明。
- 页面卸载不取消后台任务，继续依赖现有 Store 快照和任务事件恢复。
- 全局事实切换大项时保留当前编辑草稿同步逻辑；预览只读取当前草稿，不额外保存。

## 验证

1. 为紧凑进度组件和关键页面结构增加定向测试，先失败后实现。
2. 运行相关 `node --test` 测试。
3. 在 `client/` 运行 `npm run build`。
4. 启动 `npm run dev`，分别检查 STEP 01 至 STEP 06、技术方案入口和已有方案扩写入口。
5. 在默认 `1440x920` 和最小 `1040x720` 窗口下，分别覆盖应用侧栏展开、收起两种状态，检查双栏/标签切换、内部滚动、全屏 Markdown、弹窗、编辑/预览切换及底部悬浮工具条遮挡。
6. STEP 05 额外检查运行、暂停中、已暂停、失败待决策，以及编排、原方案还原、字数调整、内容矫正、配图阶段的标签和操作入口。

## 非目标

- 不新增 STEP 06 扩写后台任务。
- 不改变 AI Prompt、模型配置或并发策略。
- 不改变目录、事实、正文的持久化和失效规则。
- 不改 Analytics 事件或 Dashboard 聚合逻辑。

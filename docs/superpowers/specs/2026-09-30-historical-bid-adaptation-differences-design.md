# 历史标书适配差异确认设计

## 目标

在“历史标书适配”环节二完成完整招标基线后，开放环节三“差异确认”。系统对比 18 项招标基线与历史标书原文，形成可编辑、可逐项确认的差异台账；所有差异均处理后进入“等待验收”，环节四仍保持锁定。

## 产品边界

- 环节三只确认后续改写规则，不修改历史标书目录或正文。
- 差异类型固定为“删除内容、名称地点替换、数据更新、工期进度更新、其他人工判断”。
- 字数扩写或删减不进入本阶段，也不得由模型输出为差异项。
- 模型结果必须同时给出历史标书依据、招标基线依据和建议处理方式；无依据的推测不进入台账。
- 用户可调整差异类型、编辑处理要求，并将差异标记为“已确认”或“无需处理”。两种状态都算已处理。

## 数据与任务

- 新增受管任务 `historical-adaptation-difference`，按项目隔离并沿用技术方案任务队列、事件订阅和中断恢复规则。
- 输入为 Store 中已成功提取的 18 项招标基线及 `original-plan.md` 历史标书原文。
- 结果和确认时间保存在项目级 `technical_plan_meta` JSON 字段中，任务状态继续使用项目级 `technical_plan_tasks`。
- 重新分析会生成新的差异集合；内容标识相同的旧差异保留用户的处理状态、处理类型和修改后的要求。

## 页面结构

页面保持六阶段顶部导航。主体为紧凑的差异台账：顶部显示项目名称、分析操作和确认进度；左侧筛选差异类型及待确认状态；中央按优先级展示差异条目；条目内并列显示历史标书现状、招标基线要求和处理要求，并提供类型选择、备注编辑、确认与无需处理操作。

## 状态规则

- 环节二未完整完成：环节三锁定。
- 环节二完成、尚未分析：环节三显示“可开始”。
- 对比任务运行：显示后台进度，离开页面不取消。
- 对比完成但存在待确认项：环节三显示确认数量，环节四锁定。
- 所有差异已确认或无需处理：环节三显示“等待验收”，环节四仍锁定。
- 模型返回零项差异时视为分析完成，进入“等待验收”。

## 验收标准

1. 只有完整提取 18 项招标基线后才能进入环节三。
2. 对比任务读取历史标书原文和招标基线，页面卸载不取消任务。
3. 差异结果不包含字数扩写或删减建议。
4. 用户编辑和确认结果写入 SQLite，重新打开项目仍保留。
5. 环节四始终保持锁定，等待用户验收环节三后再实施。
6. 760px 窄屏下差异台账可读、可滚动且操作不重叠。

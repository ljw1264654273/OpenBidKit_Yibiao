# 正文层次首行缩进设置设计

## 背景

模板设置的“正文样式”已经支持普通正文的“首行缩进（字符）”，正文层次也已经支持分别配置编号样式、字体和字号。但正文层次目前没有独立的首行缩进配置，导致不同层次的有序正文只能共享普通正文的排版规则。

## 目标

在“模板设置 → 正文样式 → 正文层次”的每个层次设置中增加“首行缩进（字符）”：

- 现有可配置的第一层至第四层均可独立配置；超过第四层的正文仍沿用现有带圈数字回退规则，不新增第五层配置字段。
- 默认值为 `0` 字符。
- 支持用户自定义数字值，沿用现有数字配置的半字符步进。
- 配置保存后在实时预览和 Word 导出中生效。
- 旧模板、旧导出模板文件和缺少新字段的数据继续可正常读取。

## 非目标

- 不改变普通正文 `body_text.first_line_indent_chars` 的含义。
- 不改变列表整体左缩进 `body_text.list_indent_chars` 的含义。
- 不新增模板文件版本或数据库迁移。
- 不调整正文层次数量、编号样式、字体或字号的既有规则。

## 配置模型

扩展 `BodyOutlineLevelConfig`：

```ts
interface BodyOutlineLevelConfig {
  numbering_style: OrderedListStyle;
  font: string;
  size: string;
  first_line_indent_chars: number;
}
```

默认正文层次数组中的四层 `first_line_indent_chars` 均为 `0`。如界面或现有代码中存在第五层回退文案，也不代表第五层有独立配置；第五层继续使用导出服务已有的自动回退样式，并按 `0` 处理首行缩进。

兼容规则：

- Renderer 读取旧模板时，如果正文层次缺少字段，由默认配置补为 `0`。
- Main 侧配置规范化同样为缺少字段的层次补为 `0`。
- 不改变已有模板文件版本 `1`。
- 使用 `typeof value === 'number'` 区分“配置为 0”和“字段缺失”，确保显式的 `0` 不被默认逻辑覆盖。

## 界面行为

正文层次的每个层次卡片新增数字输入：

- 文案：`首行缩进（字符）`
- 最小值：`0`
- 最大值：`10`
- 步长：`0.5`
- 初始值：`0`

普通正文区域现有的“首行缩进（字符）”输入保持不变。正文层次输入通过现有的 `updateBodyOutlineLevel(index, updates)` 更新当前层次对象，保存时随 `body_text.body_outline_levels` 一起持久化。

## 预览行为

导出格式 CSS 变量为四个可配置正文层次提供对应的首行缩进变量：

- `--ef-body-outline-1-indent`
- `--ef-body-outline-2-indent`
- `--ef-body-outline-3-indent`
- `--ef-body-outline-4-indent`

变量值使用 CSS `em`，数值来自对应层次的字符数，`em` 基准为对应层次列表项自身的字号。具体应用在对应层级的 `ol > li`、`ol > li > ol > li` 等列表项及其直接正文段落选择器上，保证只有该层列表项的首行正文缩进，编号伪元素显式保持 `text-indent: 0`，后续换行正文保持该列表项的正常左边界；嵌套 `ol` 显式重置为 `text-indent: 0`，第五层列表项也显式按 `0` 处理。

编辑输入后配置状态立即更新，右侧实时预览立即反映对应层次的首行缩进；保存只是持久化当前配置，不延迟预览生效。

有序列表的每级 `ol` 或对应列表项使用自身层次的缩进值。层次缩进值只影响列表项正文的首行，不覆盖编号区域的列表左缩进和编号悬挂布局。第五层回退样式没有独立缩进值，按 `0` 处理。

旧配置缺少该字段时预览按 `0` 处理。

## Word 导出行为

导出服务继续使用现有编号引用和 `body_outline_levels` 生成有序列表编号配置：

- 每个编号层级读取自身 `first_line_indent_chars`。
- 使用导出服务已有的 `charsToTwips(chars, bodyRunSize)` 换算为 twips，其中 `bodyRunSize` 使用该正文层次字号对应的 Word half-points。
- 将换算结果写入列表项段落自身的 `firstLine`，编号层级的 `left` 和 `hanging` 保持不变；编号标记继续由编号层级缩进定位，首行额外按 `firstLine` 偏移，后续换行遵循 Word 的列表段落缩进规则。
- 普通正文段落继续读取 `body_text.first_line_indent_chars`，不受正文层次配置影响。
- 无新字段的旧模板按 `0` 处理。

当正文层次配置为 `0` 时，不生成额外的首行缩进；当配置为正数时，编号层级的段落首行按对应字符数缩进。

## 测试策略

增加或扩展现有导出服务测试：

1. 构造四个正文层次分别使用不同首行缩进值的导出配置。
2. 导出包含四层有序正文的 DOCX。
3. 解析 `word/numbering.xml`，确认每个正文编号层级保留各自的 `left`/`hanging`；同时解析 `word/document.xml`，确认每个层次的列表项段落带有按自身字号换算的 `firstLine`。
4. 验证第五层自动回退仍可导出且首行缩进按 `0` 处理。
5. 验证普通正文段落仍使用全局正文首行缩进。
6. 验证缺少正文层次首行缩进字段的旧配置按 `0` 处理。

旧模板兼容范围包括：数据库中已保存但字段缺失的模板配置，以及导入的 `.yibiao-template.json` 文件中正文层次字段缺失的配置；两者均由现有模板配置合并逻辑补成 `0`，不改变文件格式版本。

Renderer 侧以 `npm run build` 验证类型和打包，确保新增字段在默认配置、模板合并、界面更新和 CSS 变量生成链路中完整贯通；预览验收以编辑任一层次输入后右侧对应层次首行发生变化、且编号标记位置不随之漂移为准。

# 客户端全局 UI 风格统一设计

## 背景

当前客户端各功能页面的布局、面板处理和圆角尺度不完全一致。用户指定“新建标书”页面作为全局视觉参照，希望所有用户可见页面统一到该标准；知识库页面还缺少返回知识库二级目录列表的入口。

## 目标

- 统一客户端所有用户可见业务页面与配套弹窗的基础视觉规则，参照 `BidProjectCreatePage` 及 `feature-bid-project.css`。
- 重点统一页面背景与留白、标题和操作区、面板边框与圆角、按钮和输入控件的形状与尺寸。
- 在本地知识库分类页面增加返回“标书知识库”二级目录列表的入口。
- 保留各功能已有的信息架构、业务行为、页面状态与工作流。

## 范围

纳入主客户端所有用户可见业务页面，包括标书目录、新建标书、方案扩写、以标写标、模板、知识库、技术方案与可行性报告工作台、查重/废标/技术方案检查、商务标和设置，以及这些页面配套的弹窗、空态和加载状态。

排除开发者测试页、调试工具页及不面向普通用户的内部窗口。本次不调整侧边栏信息架构，不改变业务逻辑、数据、IPC 或持久化协议。

## 统一 UI 基线

- 以新建标书页的克制风格为参照：清晰的页面标题与说明、明确的主次操作、浅色页面底和白色内容面板、轻量边框，不引入新的视觉主题。
- 圆角统一采用小而克制的尺度：内容面板不超过 8px；输入框和常规控件不超过 6px。按钮沿用客户端共享按钮样式，并与新建标书页保持一致；不保留个别页面特有的大圆角或胶囊形容器。
- 页面间距、字体层级、边框色、控件高度和焦点态优先复用已有全局 token 与共享样式。若现有 token 无法表达该基线，只在实现所需范围内补充或调整共享 token。
- 每个页面继续使用自己的功能布局；只有为满足统一基线所必需时，才调整局部结构，不把所有页面强制改造成同一张模板。
- 保持页面根容器高度和内部滚动约束，不依赖 body 滚动；弹窗继续使用共享 Dialog 体系。

## 页面与导航行为

本地知识库分类页顶部当前显示“本地知识库 / 分类名”。将“本地知识库”改为清晰可识别的返回操作，点击后回到 `bid-knowledge-base` 二级目录列表。分类名、文件夹/文档数量以及新建文件夹和上传操作仍保留在当前页面。

知识库主列表、查看文档、文件夹管理和相关弹窗都纳入统一视觉基线；其现有筛选、排序、拖拽、上传、移动、删除和后台处理行为保持不变。

## 实施方式

1. 以新建标书页面和现有共享 token 为依据，盘点页面级样式、圆角、间距、面板和控件差异，确定少量可复用的全局规范。
2. 先迁移知识库，覆盖分类页、文档查看状态和配套弹窗，并实现返回二级目录入口。
3. 按功能模块逐步迁移其他用户可见页面和弹窗；每个模块保留业务结构，只调整视觉表达。
4. 对照参照页复查剩余页面，修正遗漏的大圆角、容器风格偏差和页面滚动问题。

## 验收标准

- 用户可见业务页面和配套弹窗使用一致的页面底色、面板边框、圆角尺度、控件样式与标题/操作区层级。
- 内容面板圆角不超过 8px，输入及常规控件圆角不超过 6px；不残留与参照页明显冲突的大圆角或胶囊形面板。
- 知识库分类页可以从顶部返回“标书知识库”二级目录列表。
- 各页面原有操作、数据、流程状态和业务工作流不变；长内容仍在页面内部滚动，弹窗可在目标窗口尺寸内正常使用。
- `cd client && npm run build` 成功；按模块手动检查页面布局、弹窗、空态及滚动行为。

## 不在本次设计内

- 重做各功能的信息架构或合并页面。
- 改变业务流程、数据结构、IPC、存储或 Analytics 行为。
- 改造开发者测试和调试页面。
- 引入新的组件库、CSS 框架或整体视觉主题。

# 技术方案目录最小层级配置设计

## 1. 背景

技术方案 STEP 03 当前依据招标文件、技术评分项、原方案、知识库和字数容量动态生成目录。目录最多允许七级；“技术文件独立成册”模式还要求评分条目继续展开为评分要点和可独立编写的正文小节，但用户不能明确指定所有 AI 正文叶子至少达到三级、四级或五级。

这会导致同一类标书在不同模型或不同材料下生成的目录深度不稳定。用户希望在 STEP 01 的“快速配置”中预先选择目录的最低层级，并在 STEP 03 生成或重新生成目录时使用同一配置。该约束必须由提示词和程序校验共同保证，不能只依赖模型自行遵循。

## 2. 目标

1. STEP 01“快速配置”增加目录层级选项：默认、三级、四级、五级。
2. STEP 03“生成目录/重新生成目录”弹窗展示并允许修改同一份项目配置。
3. 两个入口双向同步；任一处修改后，另一处立即读取同一持久化值。
4. 选择三级、四级或五级时，技术分支中的 AI 正文叶子至少达到对应绝对层级。
5. 目录达到最低层级后仍可按材料复杂度继续展开，但继续遵守现有最多七级限制。
6. Agent 的子目录生成、叶子调整、最终审核和自动复检均使用固化后的层级约束。
7. 宿主程序确定性校验目录深度；不允许使用单子节点、重复标题或空泛标题机械凑层级。
8. 当前配置与目录生成成功时的生效快照分开保存，配置变化后提示重新生成。
9. 旧项目、新建项目和未显式选择的项目保持当前动态生成行为。
10. 同时兼容 `technical-plan` 和 `existing-plan-expansion` 两个共用工作流。

## 3. 非目标

1. 不改变一级目录确认流程和评分规划确认流程。
2. 不修改目录最多七级的现有限制。
3. 不要求模板填写、点对点应答表或其他非 AI 正文节点达到最低层级。
4. 不通过生成后的机械后处理插入“详细说明”“具体措施”等占位目录。
5. 不阻止用户在目录生成完成后手工删除或合并目录；人工编辑视为用户明确决定。
6. 不改变 `saveOutline()` 的 `reason` 协议、正文失效规则或目录节点权威存储。
7. 不修改正文层次列表、Word 标题样式或导出编号规则。
8. 不删除、绕过或弱化现有 Analytics、评分覆盖、叶子数量和专业结构校验。

## 4. 已确认的业务规则

### 4.1 配置值

项目级配置提供四个值：

| 配置 | 含义 |
| --- | --- |
| 默认 | 不设置最低层级，保持现有动态生成行为 |
| 三级 | 目标 AI 正文叶子绝对层级不得低于 3 |
| 四级 | 目标 AI 正文叶子绝对层级不得低于 4 |
| 五级 | 目标 AI 正文叶子绝对层级不得低于 5 |

层级从一级目录开始绝对计数：`1` 为一级，`1.2.3` 为三级，`1.2.3.4.1` 为五级。该值不是“在评分项下面再增加 N 级”的相对深度。

### 4.2 受约束节点

最低层级只检查同时满足以下条件的最终叶子节点：

1. 节点位于评分规划确认的技术分支中。
2. 节点的 `content_mode` 为 `ai-generate`。

以下节点豁免：

- `template-fill`。
- `point-to-point`。
- `other`。
- 未纳入技术评分目录规划且按现有规则保持原样的非技术分支。

最终持久化节点没有稳定的“本次 Agent 新增”或“固定不可展开”来源标记，因此确定性校验不得尝试按不可判定的来源豁免。只要节点位于评分规划技术分支且最终是 `ai-generate` 叶子，就必须满足所选最低层级。招标文件固定目录只有在它本身是非 AI 模式或不属于评分规划技术分支时才豁免；技术分支中的固定评分标题可以保持标题不变，但其下级 AI 正文结构仍须继续展开。

普通标书生成和已有方案扩写共用该规则。已有方案扩写选择三级、四级或五级时，Agent 可在不改变原方案权威语义和评分映射的前提下继续展开 AI 正文叶子；选择“默认”时保持当前行为。

### 4.3 展开质量

为了达到最低层级而继续下钻时：

- 每个新父节点原则上至少包含两个独立、具体、非重复的写作单元。
- 继续遵守现有“不得生成单子节点冗余层级”的规则及其招标来源层级例外。
- 标题必须是有业务含义的名词性短语，不得使用“详细说明”“相关内容”“具体措施”等空泛占位标题。
- 不得改变用户确认的一级目录、评分项映射、评分项目标层级和固定标题。
- 不得为了满足深度删除或合并评分来源，不得把非 AI 叶子改成 AI 叶子。
- 复杂内容可以继续展开到六级或七级，不要求所有分支最终深度完全一致。

### 4.4 人工编辑

完整目录生成成功后，用户手工增删改目录属于明确人工决定，不因最低层级配置而被保存接口拦截，也不自动重新展开。再次执行以下操作时重新使用当前最低层级配置：

- 重新生成完整目录。
- 使用 AI 为节点生成子目录。

纯人工编辑继续沿用现有目录失效和正文清理规则。

- 左侧标题：`目录层级`。
- 辅助文案：`AI 正文目录最低深度`。
- 右侧使用与篇幅档位一致的单选胶囊：`默认 / 三级 / 四级 / 五级`。
- 说明文案：`STEP 03 目录生成时仍可调整，复杂内容最多可展开到七级。`

- `目录 默认`
- `目录 三级`
- `目录 四级`

### 5.2 STEP 03 目录生成弹窗

- 选项：`默认 / 三级 / 四级 / 五级`。

若已有目录且当前值与生成成功时的快照不同，显示现有风格的提示：

## 6. 状态与持久化

### 6.1 Renderer 状态

`TechnicalPlanState` 增加：

- `outlineMinimumDepth`：当前可编辑配置，建议使用联合类型 `0 | 3 | 4 | 5`，其中 `0` 表示默认。
- `outlineMinimumDepthSnapshot?: 0 | 3 | 4 | 5`：当前目录生成成功时的生效值；没有有效目录时为空。

选择数值型存储值可以直接进行层级比较；UI 负责把 `0` 映射为“默认”。所有读取入口必须归一化非法值为 `0`。

### 6.2 SQLite

`technical_plan_meta` 增加：

- `outline_minimum_depth INTEGER NOT NULL DEFAULT 0`
- `outline_minimum_depth_snapshot INTEGER`

运行时 migration 以 `client/electron/services/sqliteDatabase.cjs` 为权威，并同步更新 `sql/workspace_schema.sql`。旧数据库迁移后当前值为 `0`、快照为空，因此不改变既有目录行为。

当前工作区的每个项目使用 `technical_plan_project_<id>_meta` 动态项目表，Store 会把根表 SQL 重写到项目表。因此 migration 不能只更新根 `technical_plan_meta`：

1. 根表和新建项目 schema 都要包含两列。
2. migration/项目 Store 初始化必须枚举或定位已有 `technical_plan_project_*_meta` 表，并使用 `addColumnIfMissing` 补齐两列。
3. schema 健康检查应把当前 schema 版本下仍缺少两列的动态项目表视为待修复，而不是允许其进入读写后报 `no such column`。
4. migration 必须在项目 Store 加载新字段前完成。

目录被清空、导入重置、切换标段或其他现有下游清理路径清除 `outlineWordControlSnapshot` 时，也必须清除 `outlineMinimumDepthSnapshot`。派生标书或项目变体继承当前配置，但新目录尚未生成，因此快照保持为空。

同源派生标书的 `exportVariantSeed()` / `importVariantSeed()` 显式传递并归一化 `outlineMinimumDepth`：来源项目选择五级时，派生项目当前值仍为五级，但 `outlineMinimumDepthSnapshot` 强制为空。没有来源 seed 的新建项目和已有方案扩写项目默认使用 `0`。

### 6.3 配置保存

现有 `saveOutlineConfig()` 请求增加 `minimumDepth`。STEP 01 和 STEP 03 都通过该接口保存完整目录配置：

- 参考知识库选择。
- 远程知识库范围。
- 目录模式。
- 已有方案目录使用方式。
- 字数控制。
- 最小目录层级。

Renderer、preload、IPC 和 Store 之间只传递该值，不重复堆叠内部校验；Store 在持久化边界统一归一化为 `0 | 3 | 4 | 5`。

## 7. 目录任务数据流

1. 用户在 STEP 01 或 STEP 03 修改当前配置。
2. 点击生成目录后，任务 payload 写入 `minimum_outline_depth`。
3. 任务启动时优先使用 payload；恢复旧任务时使用持久化 resume payload；两者缺失时读取 Store 当前配置并归一化为默认。
4. 任务开始后不再读取可能被修改的当前配置，保证一次运行中的各阶段使用同一值。
5. 子目录生成、叶子调整、最终审核、审核修复均接收该值。
6. 最终目录通过全部确定性校验后，Store 同时写入：
   - `outlineData`
   - `outlineWordControlSnapshot`
   - `outlineMinimumDepthSnapshot`
7. 任务失败或取消时不得更新层级快照。

任务暂停恢复所需的 Agent resume payload 增加 `minimum_outline_depth`，确保应用重启后仍恢复原任务约束，而不是使用用户后来修改的当前值。

### 7.1 状态与事件传播清单

当前值和快照必须完整进入现有状态传播链，避免只在页面本地保存后短暂同步：

- 初始技术方案状态和 `TechnicalPlanState` 默认值。
- `createTechnicalPlanUserSettings()` 返回的当前项目设置。
- Store 的完整加载结果和任务快照。
- `buildTechnicalPlanSnapshot()` 及目录任务的 created/running/success/error patch。
- 目录任务启动时显式清空旧 `outlineMinimumDepthSnapshot`。
- 成功 checkpoint 与 `outlineData`、字数快照一起推送新快照。
- 导入、切换标段、清空目录和项目重置事件显式推送 `outlineMinimumDepthSnapshot: undefined`。
- `TechnicalPlanHome` 的完整加载、任务事件合并、目录清空和重置分支。

当前可编辑值不因任务启动而清空；只有生效快照随目录生命周期清理。任务事件到达后无需重新加载页面，STEP 01 和 STEP 03 就应看到相同的当前值与快照。

## 8. Agent 约束

### 8.1 子目录生成

`createChildrenPrompt()` 增加按配置生成的指令：

- 默认：不增加最低层级指令。
- 三级、四级、五级：明确所有受约束的 `ai-generate` 叶子必须达到对应绝对层级。
- 为达到层级而展开时必须产生至少两个有独立写作价值的子节点。
- 评分语义、评分覆盖、用户确认结构和专业质量优先；如果无法在不编造内容的情况下满足约束，应由最终校验暴露问题，不得写入空泛目录。

### 8.2 叶子调整

`createLeafAdjustmentPrompt()` 在调整叶子数量时继续携带最低层级规则。Agent 不得为了达到叶子数量目标把合格的深层结构压缩到最低层级以下，也不得通过浅层新增叶子破坏层级约束。

### 8.3 最终审核和修复

最终审核上下文增加：

- 当前最低层级。
- 受检查 AI 叶子数量。
- 未达到最低层级的节点 ID、标题和实际层级。

最终审核和自动复检提示词要求优先修复这些节点，同时继续满足评分映射、最多七级、无冗余单子节点、标题质量和叶子数量容量限制。

## 9. 确定性校验

在 `buildOutlineReviewContext()` 中增加 `minimum_depth` 检查结果，建议结构为：

```json
{
  "configured": 5,
  "enabled": true,
  "checked_ai_leaf_count": 42,
  "shallow_ai_leaves": [
    { "id": "1.2.3.4", "title": "进度控制措施", "depth": 4 }
  ],
  "valid": false
}
```

检查算法：

1. 根据 `scoreDirectoryPlan.branches[*].branch_id` 找到技术分支根节点。
2. 递归遍历这些根节点，使用实际父子结构计算绝对层级，不仅依赖可被错误写入的 `id` 文本。
3. 对 `content_mode=ai-generate` 的叶子判断 `depth >= configured`。
4. 默认模式直接返回 `enabled=false`、`valid=true`。
5. 非 AI 叶子不进入 `shallow_ai_leaves`。

最终确定性审核必须同时满足：

- 现有最终目录验证通过。
- 叶子数量/严格容量验证通过。
- 结构验证通过。
- 评分映射验证通过。
- 独立技术文件专业结构验证通过。
- 最小层级验证通过。

发现浅层叶子时沿用现有最多两轮审核修复流程。达到修复上限后仍失败，任务报错应包含配置层级、未达标数量和首批节点标题，不能静默接受当前结果。

## 10. AI 生成子目录

目录详情中的“AI 生成子目录”当前由 Renderer 直接请求一层叶子，现有协议明确禁止返回 `children`，不能满足三级至五级要求。本次将该入口的 Prompt、递归 Schema、响应归一化和校验从页面组件移到 feature 专用 service，页面只负责收集用户要求、调用 service 和按现有 `saveOutline()` 协议保存。

新的局部生成协议：

1. 操作开始时捕获当前 `outlineMinimumDepth`，本次请求过程中不再读取可能变化的状态。
2. 根据目标节点在当前树中的实际绝对深度计算还需展开的层级。
3. 结构化输出允许递归 `children`，但总体最多七级；父节点包含 `children` 且不包含 `content_mode`，叶子包含 `content_mode` 且不包含 `children`。
4. Schema 的可递归深度按目标节点剩余可用层级构造，不允许模型返回超出七级的结构。
5. 合并保存前，在 AI 外部响应边界校验本次新增子树：所有 AI 叶子达到捕获的最低层级、没有冗余单子节点、没有重复或通用空泛标题、没有超过七级。
6. 校验失败时不保存部分结果，向用户显示可操作错误；不扫描、修复或阻断目标节点以外的人工分支。
7. 对已经达到或超过目标层级的节点，仍允许按用户要求生成一层或多层有意义子目录，但不得超过七级。

该局部操作只校验本次目标节点生成的子树，不因其他人工编辑后留下的浅层分支而阻断保存。

## 11. 失效与同步规则

- 修改当前最低层级不立即替换目录，也不修改生效快照。
- 当前值与快照不一致时，STEP 03 阻止用户误以为新配置已经生效，并提示重新生成。
- 有有效目录且数据库层级快照为 NULL 时，加载和后续步骤门槛把它视为 legacy effective snapshot `0`；不回写数据库、不显示配置失配提示，也不阻止进入正文。没有有效目录时快照仍为 `undefined`。首次完整重新生成后才显式持久化本次值，包括默认值 `0`。
- 后续步骤要求“有效目录对应一个可解释的层级快照”：新目录使用显式快照，旧目录使用上述仅在加载层派生的 legacy `0`。不得像缺失字数快照一样直接拒绝旧目录。
- 重新生成目录仍按现有 `replace` 语义清空旧正文和相关下游状态。
- 人工目录编辑不自动改变当前配置或生效快照。

## 12. Analytics

现有配置使用埋点保留。目录生成配置事件在当前协议允许的前提下增加不含用户内容的 `minimum_outline_depth` 数值维度；不上传目录标题、招标文件内容、文件名或本地路径。若现有 Worker 对事件字段采用固定白名单，则同步检查 Worker 和 Dashboard，不通过删除或绕过埋点规避协议更新。

## 13. 测试设计

### 13.1 Renderer 和快速配置

- 默认值显示为“默认”。
- 选择三级、四级、五级后调用同一目录配置保存接口。
- STEP 01 修改后 STEP 03 回显一致；STEP 03 修改后返回 STEP 01 回显一致。
- 快速配置折叠摘要正确显示当前值。
- 当前配置与快照不一致时显示重新生成提示。
- 任务锁定状态下选项不可操作。
- 目录生成或目录调整运行、暂停中切回 STEP 01 时同样不可操作。
- `technical-plan` 和 `existing-plan-expansion` 均显示并保存该配置。

### 13.2 Store 和 migration

- 新数据库默认当前值为 `0`、快照为空。
- 旧数据库迁移后保持默认动态行为。
- 已存在的 `technical_plan_project_*_meta` 动态项目表迁移后可以正常加载和保存两列。
- 非法值归一化为 `0`。
- 生成成功保存快照；失败和取消不保存快照。
- 清空目录和下游重置同时清空快照。
- 项目变体继承当前值但不继承已生成目录快照。
- 来源项目为五级时，同源派生项目当前值为五级、快照为空；无来源 seed 的新项目为默认。
- 暂停恢复 payload 保留原最小层级。
- 有目录但快照为 NULL 的旧项目按生效值 `0` 继续进入正文且不显示失配；空项目仍保持快照为空。
- 任务事件可以即时传播当前值、清空快照和成功快照，不依赖页面重载。

### 13.3 目录任务

- 默认模式不产生最低层级错误，保持现有行为。
- 三级配置接受三级至七级 AI 叶子，拒绝一级和二级 AI 叶子。
- 四级配置拒绝三级 AI 叶子。
- 五级配置拒绝四级 AI 叶子，接受五级、六级和七级叶子。
- 非 AI 叶子不参与检查。
- 非技术分支不参与检查。
- 技术分支中的固定标题 AI 叶子仍参与检查，其标题保持不变、下级结构继续展开。
- 深度使用实际树结构计算，即使节点 ID 文本异常也不能绕过。
- 最低层级与最多七级、评分覆盖、叶子数量和专业结构同时生效。
- 自动复检能够接收浅层节点明细；达到修复上限仍失败时返回明确错误。
- 局部 AI 子目录生成只校验目标子树。
- 局部 AI 子目录支持递归结构，根据目标节点实际深度补足三级至五级，并拒绝超七级、单子节点、重复和空泛标题。

### 13.5 人工验收路径

1. 在 STEP 01 分别选择默认、三级、四级、五级，确认摘要和保存回显。
2. 进入 STEP 03，确认同一值；修改后返回 STEP 01，确认同步。
3. 选择四级生成目录，确认所有技术 AI 正文叶子至少达到四级。
4. 选择五级重新生成，确认浅层技术叶子被继续展开，复杂内容仍可出现六级或七级。
5. 检查模板填写、点对点应答表和其他模式未被机械加深。
6. 修改已生成目录对应的当前配置，确认出现重新生成提示，但当前目录不会立即被清空。
7. 手工把一个目录改浅并保存，确认人工操作不被阻断；重新生成后再次遵循配置。
8. 退出并重启应用，确认当前配置、快照和暂停任务约束能够恢复。
9. 在已有方案扩写入口重复检查默认和数值层级配置。

# 历史标书适配正文迁移与检查流程设计

## 目标

将正文迁移与一致性检查解耦，避免点击第五步“建立/更新迁移”后自动执行耗时的全文检查，并允许人工在未检查或检查存在问题时继续确认和导出。

## 用户流程

- 第五步只负责建立迁移方案、执行正文迁移、查看和编辑章节正文，以及确认进入第六步。
- 正文迁移完成后不自动启动一致性检查。
- 第五步确认时，一致性检查未执行、已过期或存在阻断结果时仅弹窗提示；迁移未完成、任务仍运行等流程性阻断仍禁止确认。
- 第六步集中提供可选的一致性检查入口和检查结果展示。
- 第六步不要求一致性检查结果存在、最新或无阻断，用户可以直接进行后续人工终审或导出。
- 导出 Word 前统一弹窗提示未检查、检查过期或存在检查问题的风险，用户确认后继续导出。

## 实现边界

1. Main 任务服务移除正文迁移成功后的自动检查调度。
2. Store 的阶段确认和导出前置条件不再把一致性检查快照作为硬阻断；仍保留迁移状态、活动任务和必要正文状态校验。
3. Renderer 从第五步移除一致性检查操作区；第六步复用同一检查任务和结果，并提供导出风险确认弹窗。
4. 现有一致性检查规则、统计、埋点和结果持久化保持不变，仅调整触发和是否阻断流程。

## 验证

- 增加/更新 Main 任务服务与 Store 定向测试，覆盖不自动检查、未检查可确认、存在阻断可提示后确认、未检查可导出。
- 运行相关 `node --test` 测试和 `cd client; npm run build`。

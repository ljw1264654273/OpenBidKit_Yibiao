# 标书项目管理设计

**日期：** 2026-09-14  
**范围：** 方案 B：本机标书项目工作区

## 目标

把当前只能承载一份技术方案的单例流程，改造成可持久化管理多份本机标书项目的工作区。每份项目独立保存招标文件、解析结果、目录、正文、任务状态和导出上下文，用户可以从列表重新打开并继续编辑。

## 已确认的产品行为

- 工作区内可以并存多份标书，不因新建覆盖旧项目，退出软件不丢失。
- 列表支持名称搜索、状态筛选和类型筛选；状态至少包括生成中、未完成、已完成、生成失败。
- 项目支持打开、继续编辑、导出、重命名和直接删除；删除前二次确认，不进入回收站。
- 同一招标文件允许新建多份标书。源文件重复识别只提醒并列出已有同源项目，不阻止继续创建。
- 新建项目自动显示同源序号；用户可以为项目填写标段/包件标识，避免多份方案混淆。
- 同一招标文件下的项目默认纳入正文段落级查重；也支持手动勾选任意两份本机项目发起比对。
- 查重结果为左右对照视图，重复段落两侧联动高亮，并提供改写建议；只在用户确认后替换，不自动改写。
- 招标文件原话、规范条文和公司固定资质介绍等可豁免内容不标红。默认灵敏度固定为中等，保留后续调整入口。
- 比对范围仅为本机当前工作区内的标书，不上传文件内容，不跨用户和设备。
- 多项目可以同时生成；同一项目内仍保持现有任务互斥，跨项目由有限并发队列控制，默认上限为 2。
- 本期不做多人协作、跨设备同步、云端共享、完整商务标平台和存量单例数据迁移。

## 架构

### 项目实体

新增 `bid_projects` 作为项目目录，保存项目名称、类型、状态、来源文件指纹、标段/包件标识、当前步骤、创建/更新时间和删除信息。项目数据位于 SQLite，项目专属文件位于 `userData/workspace/bid-projects/<projectId>/`。

技术方案现有 `technical_plan_*` 表和文件路径不再使用全局单例语义；通过 `project_id` 关联到 `bid_projects`，所有查询、写入、清理和文件路径解析均以当前项目为边界。旧的单例表保留用于兼容结构检查，但新建项目不再写入旧单例。

### 源文件指纹

上传时同时记录：

1. 原始文件字节 SHA-256（同一文件完全重复时快速命中）。
2. 解析后 Markdown 的归一化 SHA-256（重新下载导致文件字节变化、正文一致时命中）。

命中后返回同源项目摘要，由 Renderer 弹出提醒。确认继续创建时生成新的项目，并将其 `source_group_id` 设为同源组；不把重复判断变成唯一约束。

### 项目状态

项目状态不是由 Renderer 推断后写回，而是由 Main Store 根据项目步骤和任务状态计算：

- `generating`：项目绑定的任一生成任务运行中、暂停中或排队中。
- `failed`：最近一次生成任务失败。
- `completed`：正文至少有一个有效生成结果且没有未处理失败任务。
- `incomplete`：其余已创建但尚未完成的项目。

项目列表读 Main 的聚合快照；任务事件携带 `projectId`，Renderer 只更新对应项目或当前打开项目。

### 任务并发

`taskService` 的任务定义增加 `project_id`/`scope_id`。同一项目保持现有技术方案组内互斥；不同项目允许进入共享的有限并发调度器。默认最多同时运行 2 个技术方案生成任务，超出任务进入排队状态并在项目列表显示“生成中/排队”。

任务取消、项目删除和导入覆盖均先取消并等待该项目的活动任务 settled，再清理项目数据和文件，避免旧 runner 继续 checkpoint 到已删除项目。

### 正文查重

复用项目正文的 Markdown/目录数据，在 Main 中按段落拆分和归一化，使用字符 n-gram + 编辑距离的混合近似判定，默认中等灵敏度。短段落、纯编号、纯引用和命中豁免规则的段落跳过。

查重结果保存到项目查重结果表，包含左右项目、段落 ID、原文范围、相似度、豁免原因和建议。Renderer 负责对照展示、双向定位和用户确认；确认后通过当前项目正文编辑 IPC 使用既有文本编辑规则替换指定段落。

## 页面

### 工作区首页

新增“标书项目”页面作为标书生成入口。首页显示统计、搜索和筛选、项目列表以及同源查重提醒。每个项目行显示名称、来源文件、类型、同源序号、最近编辑时间和状态，并提供打开、重命名、查重、导出、删除。

### 单项目详情

打开项目后沿用现有技术方案步骤页面，顶部显示返回列表、项目名称、同源序号和导出；左侧步骤导航仍为招标文件、招标分析、目录、全局事实、正文、扩写；右侧显示项目状态、同源项目和查重快捷入口。所有现有页面调用自动带当前 `projectId`。

### 新建流程

从首页点击新建后上传招标文件。Main 返回源文件重复命中摘要；Renderer 先展示已有项目并提供“打开已有项目”和“继续新建”。继续新建时填写可选标段/包件标识，创建新项目并进入当前项目的招标文件步骤。

### 查重页面

首页和项目详情均可进入查重页面。默认列出当前同源项目并自动准备比较；手动模式提供本机项目选择器，至少选择两份。结果页左右展示两份正文，重复段落使用同一组颜色和联动定位，右侧显示相似度、豁免原因和改写建议。

## 错误处理

- 项目删除、重命名、查重替换和继续新建失败均通过 Toast 提示；需要确认或解释时使用 AppDialog。
- 单个项目任务失败只标记该项目，不影响其他项目；列表操作提供查看原因和重试。
- 项目数据缺失时显示可恢复错误，并允许从列表删除损坏项目；不静默创建空项目。
- 项目文件清理遵循现有强制删除工具，中文 Windows 路径显式使用 UTF-8；删除失败时保留错误提示，不删除数据库记录。

## 验收

- 新建第二份标书不会覆盖第一份，退出并重新进入后两份均可打开。
- 两份不同项目可同时运行正文生成，第三份在并发上限外排队；每份任务进度和失败信息只更新自己的项目。
- 同一源文件再次上传时提示已有项目，但选择继续后能创建新的同源序号项目。
- 不同文件不触发源文件重复提示；同正文不同字节文件在归一化指纹相同的情况下可以提示。
- 项目列表的搜索、状态/类型筛选、重命名、直接删除和导出均作用于正确项目。
- 同源正文和手动两项目查重均能返回左右段落对照；改写建议未确认前不改变正文，确认后只替换目标段落。
- 数据库迁移、Electron Main/preload 类型链路、现有技术方案和独立查重页面不回归。

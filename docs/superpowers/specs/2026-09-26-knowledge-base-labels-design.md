# 知识库分类名称调整设计

## 目标

将五类本地知识库的中文显示名称统一调整为文档名称：

| 旧名称（含仓库现状与用户口径） | 新名称 |
| --- | --- |
| 国标知识库 / 国标数据库 | 国标文档 |
| 省标知识库 / 省标数据库 | 省标文档 |
| 市标知识库 / 市标数据库 | 市标文档 |
| 行业标知识库 | 行业标文档 |
| 企业知识库 | 企业文档 |

## 范围与边界

- 同步客户端知识库目录、页面相关显示文案、Analytics Dashboard 路由中文名、知识库分类测试期望值，以及仓库内既有设计文档、计划和 README 中对应的说明。历史文档也统一使用新名称，不保留旧显示名称。
- 仅替换上述五类中文名称；通用名称“文档知识库”保持不变。
- 菜单标题使用新名称。菜单描述继续保持自然表达：五类菜单分别显示“管理国标资料……”“管理省标资料……”“管理市标资料……”“管理行业标资料……”和“管理企业资料……”，不生成“管理国标文档资料……”这类重复表达；通用“文档知识库”的描述保持现状。
- Analytics Dashboard 中这五个 navigationId 的顶层、`/library` 和全部 `/viewer/*` 页面标签均同步使用新名称。
- 不修改导航 ID、数据库分类 ID、IPC 通道、英文路由、文件目录、埋点事件协议或数据库结构，确保已有工作区和统计数据兼容。

## 实现与验证

1. 对客户端、Analytics Dashboard、测试、README 和既有设计/计划文档中的五类旧中文名称做精确替换，避免修改无关的“数据库”技术术语和 `knowledge-base` 内部标识。
2. 使用 `rg` 复查旧名称。复查时排除本设计文档；其余目标目录中不应再出现需求映射表左列记录的任何旧名称。
3. 在 `client/` 执行 `npm run build`。
4. 定向执行知识库分类测试：`node --test electron/services/knowledgeBaseStore.categories.test.cjs`。

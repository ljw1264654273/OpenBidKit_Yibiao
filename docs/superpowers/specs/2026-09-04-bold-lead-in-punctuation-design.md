# 正文加粗引导语标点规范化设计

> 2026-09-11 更新：标书模板强制内容规范取代原“内部已有冒号时改用逗号”的处理。行内加粗引导标题现在一律以加粗范围内的中文冒号结尾；同层级两个及以上并列论述分项必须按出现顺序使用连续阿拉伯数字序号。

## 目标

仅修复后续新生成或调整并写回的技术方案正文，避免 Markdown 加粗引导语出现不符合语义的句号：行内引导语使用冒号，独立成行的引导语不保留句号。

## 范围与约束

- 不修改已有 SQLite 正文，不在 Word 导出阶段改写内容。
- 覆盖正文首次生成、原方案优化扩写、字数调整等现有写回路径。
- 只处理 Markdown 完整加粗片段（`**...**` 或 `__...__`），代码围栏内内容保持原样。
- 不处理章节标题、表格行、普通正文句子或图片/图表标记；表格行按现有表格识别规则跳过，图片 Markdown 行整体跳过。

## 方案

在 `contentGenerationTask.cjs` 的正文保存前规范化链路中增加专用函数，并由 `normalizeLeafContentForSave()` 统一调用：

1. 先完整执行现有 `normalizeLeafContentForSave()` 内部的三步：`normalizeGeneratedMarkdown()`、`stripRepeatedChapterTitle()`、`stripMarkdownHeadingsFromLeafContent()`；再执行新的标点规范化。这样 Markdown heading 转成的加粗行也会被处理。
2. 逐行扫描 Markdown，跟踪 fenced code 状态；表格行和完整图片 Markdown 行直接保留。
3. 识别独立成行的加粗片段（允许可选阿拉伯数字前缀、行首空格和行尾空格），删除末尾的句号、冒号、逗号、分号、顿号和问叹号。
4. 识别加粗片段后仍有同一行正文的行内引导标题。标题无论原标点为何，均清理末尾标点并补一个中文冒号 `：`；加粗结束标记外的重复分隔标点一并删除。
5. 同一叶子小节出现两个及以上结构化加粗分项时，按出现顺序统一为 `1.`、`2.`、`3.`；缺号、跳号、重号和乱序都执行相同重排。
6. 其他文本原样返回，保留换行和 Markdown 结构；本次规则不扩展到普通正文句末标点。

同时更新 `buildChapterContentMessages()`、其原方案还原/优化扩写调用的同一提示规则，以及字数调整 prompt，明确要求：行内加粗引导语必须以中文冒号结尾；独立成行的加粗小标题不得带中文句号或英文句点。提示词是生成侧约束，保存前函数是确定性兜底。

## 测试

在现有 `contentGenerationTask` 测试体系中增加纯函数级测试，至少覆盖：

- 行内 `**房屋建筑信息核实。** 房屋数量核实` 转为 `**房屋建筑信息核实：** 房屋数量核实`。
- 行内 `**第一阶段：前期准备与资料对接。** 自合同签订后即启动` 转为 `**第一阶段：前期准备与资料对接：** 自合同签订后即启动`。
- 行内 `**图属一致性处理：**，各类表格` 转为 `**图属一致性处理：** 各类表格`。
- `**图属一致性处理：** ，， 各类表格` 同样转为 `**图属一致性处理：** 各类表格`。
- 独立行 `**自查自检机制。**` 转为 `**自查自检机制**`。
- 英文句点、`__...__` 形式、代码围栏和普通正文不被误改。
- 表格行、图片 Markdown、Markdown heading 转换后的加粗行、CRLF 和未闭合代码围栏均有覆盖；模块通过新增的测试专用导出暴露规范化函数，不改变业务 API。包含 `![...](...)` 或 `<img ...>` 的图片标记行整体保持原样。
- `normalizeLeafContentForSave()` 仍保留现有章节标题去重和 Markdown 标准化行为。

## 验收标准

- 新生成/调整正文写回后符合上述标点规则。
- 历史正文仅导出时保持原样。
- 定向 Node 测试通过，随后 `cd client; npm run build` 通过（允许既有 chunk 体积警告）。
